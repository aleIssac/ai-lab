## 五、需求② Tab 补全

### 当前状态（2026-10-20 19:20）：可实现，用自研扩展

输入 `def avg(` 停约 1 秒，光标后出现灰色斜体：

```
def avg(x, y):
    return (x + y) / 2
```

按 Tab 落字，结果就是上面两行（右括号不会重复）。

**实现方式换了**：不再用 Continue 的补全，改用自研扩展 `docker/autocomplete-ext/`，
直接调本地 Ollama 的 FIM 接口。Continue 仍保留，只负责需求③的对话/报错诊断。

### 走过的弯路（重要，别再重复）

| # | 坑 | 现象 | 结论 |
|---|---|---|---|
| 1 | **Ollama 0.40.6 忽略 Modelfile 的 `TEMPLATE`** | `ollama show --modelfile` 里明明写了 `TEMPLATE {{ .Prompt }}`，但生成时仍套 chat 模板（context 首 token 是 151644 `<im_start>`），模型回「It looks like you're trying to define a function...」 | 只能靠请求体 `raw:true`，所以**必须走 11435 代理**；config 直连 11434 等于没修 |
| 2 | **Continue 按模型名选 FIM 模板** | `getTemplateForModel` 要求名字同时含 `qwen` 和 `coder`；只含 `qwen` 会掉进 StableCode 分支，发 `<fim_prefix>`（少竖线），模型认不出 | 模型改名为 `qwen-coder-fim` |
| 3 | **多文件上下文带跑偏 1.5B** | 前缀带 `<|repo_name|>` / `<|file_sep|>` 时模型输出退化成 `"  \n   with"` | 关掉上下文注入 |
| 4 | **VS Code 其实能渲染**（关键转折） | 写了个只返回固定文本的测试扩展，幽灵文本正常显示 | 说明问题在 Continue 内部，不是 code-server |
| 5 | **Continue 2.1.0 本身有 bug** | 请求发出去了、token 回来了（devdata 有统计），但最终 `completion` 恒为空，幽灵文本永远 0。给打包代码打调试日志会直接让它不激活 | 放弃修 Continue，改自研 |
| 6 | **`completeBracketPairs = true` 会让补全完全不渲染** | 在本机加了这行，ghost 节点数 8 → 0 | 改为手动替换光标后的右括号 |
| 7 | 装自定义扩展被拉黑 | 先建空目录再拷文件 → 扫描读不到 package.json → 扩展被标 removed（`.obsolete` 里留记录），之后永远不加载 | 文件先拷齐再重启；必要时清空 `.obsolete` |
| 8 | 模型冷启动 6 秒 | 容器刚起来第一次补全要 6 秒以上，补全窗口早过了 | 扩展激活时预热模型，失败每 5 秒重试，最多 20 次 |

### 自研扩展说明（`docker/autocomplete-ext/`）

- `extension.js`：约 200 行，注册 `InlineCompletionItemProvider`
  - 拼 `<|fim_prefix|>前缀<|fim_suffix|>后缀<|fim_middle|>`
  - POST 到 `http://localhost:11435/api/generate`（`raw:true`，`num_predict: 32`）
  - 250ms 防抖 + 请求取消 + 8s 超时
  - 清理：剥 FIM 残留标记、拒纯空白/复读、遇「空行+顶格」截断（模型会一路往下编）
  - 状态栏显示「AI 补全」，点一下会弹一次测试请求结果
- 安装：`start.bat` 里幂等拷贝到 `~/.local/share/code-server/extensions/ailab.ailab-autocomplete-0.1.0/`
- 配置项：`ailabAutocomplete.enabled / endpoint / model / maxTokens / debounceMs / timeoutMs`

### 注释自动添加（同一扩展里，2026-10-25 新增）

原来靠 Continue 的 `Ctrl+I` 手动输入指令，现在改成**选中即加**：

| 操作 | 效果 |
|---|---|
| 选中一段代码 → `Ctrl+Alt+C` | 只给选区加注释 |
| 光标停在函数里 → `Ctrl+Alt+C` | 自动识别所在 `def`/`class` 整块（按缩进判断边界） |
| 不选中 → `Ctrl+Alt+Shift+C` | 整个文件所有顶层函数/类逐个加，从下往上改，行号不漂移 |

实现要点：
- 走 **chat 模板**，所以直连 `http://ollama:11434`（11435 代理会强制 `raw:true`，套不上模板）
- 提示词要求：只输出代码、不改逻辑、函数上方写三引号文档字符串（Args/Returns）、关键语句加 `#`
- 输出后做两道校验：去掉 markdown 围栏和开头客套话；代码行保留率 < 60% 或行数比原文少就放弃（防止模型把代码改坏）
- 用 `WorkspaceEdit` 写回，保持原文件换行符
- 实测：单函数 13 行 ≈ 6 秒；两函数整文件 ≈ 12 秒；生成质量见 `docs/img/comment-result.png`

### 报错诊断（同一扩展，2026-10-25 新增）

| 操作 | 行为 |
|---|---|
| 复制 traceback → `Ctrl+Alt+K` | 从剪贴板取报错（最顺手，演示推荐） |
| 选中 traceback → `Ctrl+Alt+K` | 只处理选区 |
| 都没有 → `Ctrl+Alt+K` | 退回当前文件的 VS Code 错误诊断 |

输出：右侧新开「报错诊断」Markdown 标签页，四段式：**类型 / 定位 / 修复 / 优化**，底部带一行"仅供参考"提醒。
不动正在编辑的文件。

提示词里的关键设计（都是实测调出来的）：
- **判据表**：`shapes cannot be multiplied` → 维度不匹配；`same device / cuda / cpu` → 设备不一致；`nan / inf` → 梯度爆炸
- **各类型修复方向**：维度调 reshape/permute、设备统一 `.to(device)`、梯度爆炸降 lr / 标准化 / `clip_grad_norm_`
- **硬约束**："不要为了消除报错去改标签形状"，否则模型会把 `y` 的形状改掉
- 一条示例（few-shot）把格式钉死

实测（`tools/_tmp/diag_test.py`）：
- 维度不匹配 3.2s：类型、定位、修复全对
- 设备不一致 3.0s：类型对，修复对（x/y 移到 cuda）
- 梯度爆炸 3.1s：类型对，但多层网络会把输出形状读错，修复可能不可用 → 演示优先用前两类

**踩坑记录**：
1. 最初绑 `Ctrl+Alt+D` —— 没用，因为 **Alt+D 是 Chrome/Edge 的地址栏快捷键**，被浏览器吞掉。改成 `Ctrl+Alt+K`
2. 命令一度"按键无反应、也不报错"：`getErrorMaterial` 里直接 `await clipboard.readText()`，
   浏览器没有剪贴板权限时抛异常，整个命令静默失败。修法：try/catch 包住，失败就跳过

### MLflow 界面汉化（2026-11-17 新增）

MLflow 3.17.1 官方**没有 i18n**（`i18n` 字样只出现在日期库里），也没有 `--lang` 参数，
界面是 React 打包产物（`build/` 27 MB、230 个 chunk），改源码等于维护一个 fork。

采用「外挂字典」方案，不改构建产物：

| 项 | 说明 |
|---|---|
| 脚本 | `docker/mlflow-zh/mlflow-zh.js`（字典约 170 条 + 6 条正则） |
| 注入 | `start.bat` 启动 MLflow 前：`docker cp` 到容器 build 目录，再用 `sed` 往 `index.html` 插入 `<script src="static-files/mlflow-zh.js">`（幂等，`grep -q` 判断） |
| 原理 | `MutationObserver` 监听 DOM，把**精确匹配**的文本节点换成中文；`placeholder/title/aria-label` 一并处理 |
| 不翻 | Run 名、参数、指标值、实验名、文件路径、图表 canvas 内文字 |
| 已知局限 | 长句被 React 拆成多个文本节点时需按片段补词条；页面改版后要补字典 |

**关键细节**：MLflow 静态资源前缀是 `static-files/`（不是 `/static`），脚本必须放在
`build/` 根目录并引用为 `static-files/mlflow-zh.js`，否则 404。

## 七、已知问题与风险

### 必须注意的坑

1. **容器重启后服务不会自动恢复** — MLflow、Streamlit、API、**Ollama 代理**、门户都要重起。验收当天一定用 `start.bat`。

2. **补全必须走 11435 代理** — Ollama 0.40 忽略 Modelfile 的 TEMPLATE，不加 `raw:true` 就会套 chat 模板，FIM 标记失效。别把 config 的 apiBase 改回 `http://ollama:11434`。

3. **补全模型名必须同时含 `qwen` 和 `coder`** — 否则 Continue 走 StableCode 分支，发错的 FIM 标记，模型输出聊天文字。

4. **门户服务器必须是多线程** — `socketserver.TCPServer` 会被浏览器 keep-alive 连接堵死，表现为端口在监听但 HTTP 返回 000。已改 `ThreadingHTTPServer`。

5. **代理绝对不能把 stream 改成 false** — Continue 会 abort，补全彻底不显示。

6. **Workspace Trust 会静默禁用扩展** — 如果补全突然失效，先看左上角有没有黄色 "Restricted Mode" 提示条。

7. **`agent-browser` 在本机必卡死** — 用 `playwright-core` + 系统 Edge 代替：
   ```bash
   NODE_PATH="C:/Users/Zeko/.workbuddy/binaries/node/workspace/node_modules" \
   node tools/verify_tab_completion.js
   ```

8. **Open VSX 下载慢** — 直连 39 KB/s，走代理 725 KB/s。下载大文件前先开代理。

9. **Git Bash 会篡改容器内路径** — `docker exec` / `docker cp` 带 `/tmp/...` 这类绝对路径时必须加 `MSYS_NO_PATHCONV=1`，否则会被转成 `C:/Users/.../Temp/...`。

10. **内置 Copilot 已禁用** — code-server 4.141 自带 `copilot` 扩展，会把侧边栏变成 Copilot 的 Chat，容易和 Continue 混淆。已改名 `copilot.disabled`。

11. **`.bat` 只能 ASCII + CRLF** — 中文注释会让 cmd（GBK）解析错位，整份脚本被切碎执行，现象是一堆 `'docker' 不是内部或外部命令`。用 Python 写文件时必须 `encoding="ascii", newline="\r\n"`。

12. **Streamlit 输入框是失焦才提交** — 用户填完 Key 直接点按钮，这次 rerun 读到的还是旧值（空），表现为"明明填了却说未提供"。现在 API Key 输入框已改成开关，不存在这个问题；但其他 `st.text_input` 仍有这个特性。

13. **Swagger 在反向代理下会 404** — 通过 `localhost:8080/proxy/8000/docs` 打开 API 文档会显示 "Failed to load API definition"，因为 Swagger 请求的是绝对路径 `/openapi.json`。**直接用 `localhost:8000/docs`**。

14. **演示文件会被"加注释"测试污染** — `test.py`、`err_demo.py` 跑过 Ctrl+Alt+C 之后里面就有中文文档字符串，再演示"一键加注释"就看不到变化。验收前必须确认这两个文件是干净底稿。

15. **MLflow 汉化脚本在容器内** — 改的是 site-packages，容器一重建就没了。`start.bat` 会自动重新注入（幂等），手动注入时必须 `docker exec -u root`。

### 资源风险

- **8 GB 内存**：Vite 构建会 OOM，前端只能用 CDN 包（已离线化）
- Spark 用 pip 安装（非完整 Hadoop 发行版），超出演示规模会缺组件
- 模型只有 1.5B，复杂代码生成质量有限
