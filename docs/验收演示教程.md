### 1.4 确认演示文件是干净底稿

打开 `test.py`，应该只有 `train_epoch` 函数和 `__main__`，**没有任何注释**。

如果里面已经有中文文档字符串，说明之前演示过，需要还原。

干净版只有 19 行（`import torch` + `train_epoch` + `__main__`），从头敲一遍最快；
或者从备份复制（本机或部署包里都有一份）：


### ③ 报错诊断（40 秒）

**要证明**：能识别典型错误类型，给出可运行的修复代码。

**操作**：

1. 在终端跑一个会报错的脚本（项目根已有 `err_demo.py`，故意写错矩阵维度）：

```bash
cd /home/coder/project && python err_demo.py
```

2. 终端里出现：

```
RuntimeError: mat1 and mat2 shapes cannot be multiplied (3x4 and 3x5)
```

3. **在终端里选中整段 traceback**（从 `Traceback` 到最后一行），`Ctrl+C` 复制
4. 回编辑器，按 **`Ctrl+Alt+K`**
5. 等 3 秒

**预期**：右侧新开「报错诊断」标签页，四段式输出：

```
【类型】维度不匹配
【定位】z = x @ y，x 是 (3,4)，y 是 (3,5)，左矩阵列数 4 与右矩阵行数 3 不一致
【修复】y = torch.randn(4, 5); z = x @ y
【优化】矩阵相乘前用 assert x.shape[1] == y.shape[0] 拦住这类错误
```

> **话术**：
> "学生把报错复制过来按一个键，模型先判断是哪类问题——形状不匹配、设备不一致、还是梯度爆炸，
> 再定位到具体变量和形状，最后给能直接替换的代码。不污染正在编辑的文件，报告在新标签页里。"

**说明局限性（主动说，比被问到好）**：
> "1.5B 的本地模型对维度、设备这两类判断很稳；梯度爆炸这种需要看多层结构的，
> 偶尔会把输出形状读错，我们演示时优先用前两类。"

## 五、验收人可能追问的问题

**Q1：这些功能都是本地部署的吗？断网能用吗？**
是。所有服务跑在本机 Docker 容器里：编辑器、补全模型（qwen-coder-fim）、对话模型（qwen2.5-coder:1.5b）、
MLflow、预测 API、RAG 全部离线。
有两处例外要如实说明：⑤⑥ 两个第三方可视化页面引用了 Google Fonts（离线时静默回退到系统字体），
Streamlit 页面默认开启使用统计（可在配置里关）。

**Q2：模型多大？为什么选 1.5B？**
qwen2.5-coder 1.5B 量化后约 1GB，这份配置是 8GB 内存的工作站。
选 1.5B 是权衡：补全和注释这类短文本任务够用（首 token 100ms 左右），
复杂推理确实不如云端大模型，这也是为什么 RAG 页面保留了切云端的入口。

**Q3：补全延迟多少？**
本机实测首 token 94～139ms，完整补全 0.5～1.4 秒（取决于补全长度）。冷启动第一次约 6 秒。

**Q4：注释质量怎么样？会不会把代码改坏？**
有防护：模型输出后会校验原文代码行的保留率，低于 60% 或行数比原文少就直接放弃并提示，
文件保持原样。实测 13 行函数约 6 秒，代码逻辑不变、只增加注释行。

**Q5：报错诊断能覆盖哪些错误？**
目前针对 PyTorch 的三类典型问题做了判据：张量形状不匹配、设备不一致（cpu/cuda）、
损失发散（NaN/Inf）。其他错误也能给建议，但准确率不如这三类。

**Q6：RAG 的知识库能加吗？**
能。往 `data/kb/` 放 `.md` 文件，重启 8502 即可（索引在进程启动时构建）。
现在有 3 篇 / 16 个片段，向量化用的是 TF-IDF 字符 n-gram，不依赖嵌入模型，所以断网可用。

**Q7：为什么 MLflow 是中文的？官方支持吗？**
官方 3.17.1 没有中文包。我们用一个注入脚本把界面文字替换成中文，不改它的构建产物，
升级 MLflow 时只需补词条。Run 名、参数、指标值保持原样——那些是数据不是界面。

**Q8：这些页面是你们开发的吗？**
⑤⑥⑦ 基于三个开源项目（TensorFlow Playground、Transformer Explainer、ConvNetJS），
我们做了本地化部署、界面汉化和离线适配，并修复了 Transformer 页面缺失 ONNX 加载器导致
推理跑不起来的问题。①②③ 的编辑器扩展和 ④ 的全套流程是自研的。

**Q9：能支持多少学生同时用？**
当前配置（8GB 内存、20 核）主要面向演示和小班教学。
代码补全的瓶颈在模型推理，并发 3～5 人会有明显延迟；要扩大规模需要加 GPU 或做请求队列。

**Q10：数据从哪来的？**
`data/raw/customer_churn.csv` 是脱敏的客户流失数据集，1545 行。
清洗后 1500 行用于训练，`data/kb/` 的三份文档是为教学编写的技术资料。

**Q11：怎么保证学生不乱改？**
编辑器是基于容器的，可以配合 Docker 卷快照做重置；当前版本没有做用户隔离，
适合一人一机或教师演示场景。

**Q12：验收后怎么维护？**
`start.bat` 一键启动，`stop.bat` 停止。所有配置在 `docker-compose.yml` 和 `.env`，
模型文件在 `ollama-models/`，整个项目目录可以整体拷到另一台机器。

## 六、现场故障应急

| 现象 | 30 秒处理 |
|---|---|
| 门户卡片显示「未启动」 | 重新跑 `start.bat`；或单独补：`docker exec ai-lab bash -c "cd /home/coder/project && /opt/venv/bin/python tools/serve_portal.py 3000 > /tmp/portal.log 2>&1"` |
| 编辑器打不开（转圈） | 容器可能刚重启，等 15 秒；仍不行 `docker restart ai-lab` |
| Tab 补全不出灰字 | 先确认光标在 `.py` 文件里；再看状态栏是否显示「AI Lab 补全」；最后检查 `docker exec ollama ollama list` 有没有 `qwen-coder-fim` |
| 加注释没反应 | 快捷键冲突，用 `Ctrl+Shift+P` → `AI Lab` → 选命令 |
| MLflow 空白页 | 必须从项目根目录启动，用 `start.bat`；手动启动容易路径错 |
| RAG 提示 404 | Base URL 改成 `http://ollama:11434/v1` |
| 8501/8502 打不开 | `docker exec ai-lab tail -20 /tmp/st.log`（RAG 是 `/tmp/rag.log`） |
| ⑤ 播放没反应 | 刷新页面；浏览器性能问题，不是服务 |

**兜底**：本机保有一份离线部署包（7.4 GB），任何服务彻底损坏可在 10 分钟内重装，数据不丢。
