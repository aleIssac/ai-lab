## 四、Tab 补全：从「不显示」到「可用」的完整过程

### 最终状态

**可用。** 输入 `def avg(` 后停约 1 秒，出现灰色斜体幽灵文本：

```
def avg(x, y):
    return (x + y) / 2
```

按 Tab 落字，结果正是上面两行。

### 排查过程中排除了什么

| 怀疑点 | 结论 |
|---|---|
| 模型不支持 FIM | ❌ 排除，`tools/check_autocomplete.py` 实测首 token 93ms，补全内容正确 |
| Ollama 套了 chat 模板 | ✅ **确实是坑**，Ollama 0.40 忽略 Modelfile 的 `TEMPLATE`，只能靠请求体 `raw:true` |
| Continue 的 FIM 模板选错 | ✅ **确实是坑**，模型名不含 `coder` 会退化成 StableCode 模板（`<fim_prefix>` 少竖线） |
| VS Code 不能渲染幽灵文本 | ❌ 排除。自写一个只会返回固定文本的测试扩展，幽灵文本正常显示 |
| inlineSuggest 被关闭 / 主题看不见 | ❌ 排除，配置为 true，把颜色改成纯红也不显示 |
| Copilot 抢占内联位置 | ❌ 排除，code-server 自带的 copilot 扩展已禁用，仍不显示 |

### 真正的结论

Continue 2.1.0（当前 Open VSX 最新版）在 code-server 4.141 / VS Code 1.141 上，
能把请求发出去、能收到模型返回的 token（devdata 里有统计），
但**最终 `completion` 恒为空**，所以幽灵文本永远是 0。

### 解法：自研一个补全扩展（`docker/autocomplete-ext/`）

不再依赖 Continue 的补全链路，直接调本地 Ollama FIM 接口：

- 拼 `<|fim_prefix|>前缀<|fim_suffix|>后缀<|fim_middle|>` 提示词
- 请求代理 `http://localhost:11435/api/generate`（`raw:true`）
- 返回 `InlineCompletionItem` 渲染幽灵文本
- 自带：250ms 防抖、请求取消、超时 8s、模型预热（避免容器刚起来时冷启动 6 秒）
- 结果清理：剥掉 FIM 残留标记、拒绝纯空白 / 复读补全、遇到「空行+顶格」就截断（模型常会一路往下编）

**踩到的额外坑**：`InlineCompletionItem.completeBracketPairs = true` 在本机会让补全**完全不渲染**
（ghost 节点数 8 → 0）。改成手动把光标后的右括号一起替换掉，效果一样且没问题。

### 怎么用

打开任意文件，正常写代码即可；状态栏右下角有「AI 补全」字样。
点它可以弹出一次测试请求的结果。Continue 仍保留用于需求③的对话/报错诊断（它的补全已关闭）。
