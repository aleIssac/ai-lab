# 需求④ 端到端流程实训 · 使用说明

> 适用对象：演示/验收时操作这套环境的人。
> 一句话概括：**三个专项共用一条业务主线（电信客户流失预测），从清洗一路做到上线**，
> 分别覆盖「AI 应用开发」「大数据开发」「大模型应用开发」三类岗位的核心技能。

---

## 一、这一项要证明什么

验收条款要求「三个专项实训」。三个专项不是三份互不相干的教程，而是**同一份数据、同一个业务目标**下的三条技术路线：

| 专项 | 技术栈 | 走完能得到什么 | 关键文件 |
|---|---|---|---|
| ① AI 应用开发 | pandas + sklearn + MLflow + FastAPI + Streamlit | 一个可调用的流失预测服务 + 可追溯的实验记录 | `courses/01-ai-app/`、`src/` |
| ② 大数据应用开发 | PySpark + Spark MLlib | 同一套清洗/训练逻辑在分布式引擎上跑通 + 作业体检报告 | `courses/02-bigdata/` |
| ③ 大模型应用开发 | 切块 + 向量化 + 检索 + 生成 | 一个答案有出处、可追溯的 RAG 问答 | `courses/03-llm-app/`、`apps/rag_app.py` |

**建议开场话术**：

> “这三个专项对应三个岗位：AI 应用工程师、大数据工程师、大模型应用工程师。
> 学生做的不是三个玩具 demo，而是同一条业务链——数据清洗、特征、训练、上线，
> 每一步都有产物、有指标、能被检查。”

## 三、专项一：AI 应用开发（约 3 分钟）

### 3.1 数据清洗 —— `courses/01-ai-app/01-数据清洗.ipynb`

在 8080 里打开这个 notebook，**右上角内核选 `python3`**（不是 Jupyter 默认内核），然后逐格 `Shift+Enter`。

| 小节 | 这一格在演什么 | 讲解要点 | 预期结果 |
|---|---|---|---|
| 1. 先看清问题 | `df.info()` + `isna().sum()` | 数值列显示成 `object`，因为混了 `N/A` 和空字符串 | 能看到 age / monthly_charge 是 object |
| 2. 类型问题 | `pd.to_numeric(errors='coerce')` | `coerce` 把转不了的值变 NaN，而不是直接抛错 | 类型变 float，NaN 数量浮出来 |
| 3. 异常值 | 业务规则过滤 | **业务规则比统计规则可靠**：年龄 999、月费为负，直接置缺失 | 异常行被清掉 |
| 4. 重复行 | 按 `customer_id` 去重 | 重复样本会让模型“背答案” | 删除 **45 行**重复记录 |
| 5. 清洗前后对比 | 打印行数 | — | **1545 行 → 1500 行** |

> 话术：“1545 行脏数据，四类问题（类型、缺失、异常、重复）全部处理，剩下 1500 行可直接训练。”

### 3.2 特征工程 —— `02-特征工程.ipynb`

重点讲两格：

- **衍生特征**：把「绝对值」变成「比率」——`total_charge / tenure_months` 比 `total_charge` 更能反映消费强度
- **构建预处理器 + 固化**：`ColumnTransformer`（数值标准化 + 类别 OneHot）用 `joblib` 存成 `models/preprocessor.pkl`

> 话术：“预处理必须和模型一起保存，否则上线时训练/推理不一致，这是最常见的生产事故。”

### 3.3 训练与实验记录 —— `03-模型训练与MLflow.ipynb`

两种方式，任选：

- **在 notebook 里逐格跑**（推荐演示，能看到过程）
- **在终端跑**：`cd /home/coder/project && /opt/venv/bin/python src/train.py`

跑完打开 <http://localhost:5001>，演示三件事：

1. 实验 `churn-prediction` 下**三条 run**，指标可以勾选对比
2. 点进 `RandomForest-200`，看混淆矩阵图（artifact）
3. 指一下每次 run 记录的参数（`n_estimators`、`C`）

实测数字（可直接引用）：

| run | accuracy | precision | recall | **f1** | roc_auc |
|---|---|---|---|---|---|
| LogReg-C0.1 | 0.8433 | 0.5294 | 0.8654 | 0.6569 | 0.9418 |
| LogReg-C1.0 | 0.8467 | 0.5366 | 0.8462 | 0.6567 | 0.9429 |
| **RandomForest-200** | **0.8733** | 0.5875 | 0.9038 | **0.7121** | 0.9374 |

> 话术：“三组超参实验，F1 从 0.657 提到 0.712。每次尝试都有记录、可复现——这就是 MLflow 的价值。”

### 3.4 部署发布 —— `04-部署发布.ipynb` + API

1. 先讲**本地推理**：加载 `models/model.pkl`，对单条样本预测，确认结果合理
2. 再打开 <http://localhost:8000/docs>，展开 `POST /predict` → Try it out，填入：

```json
{"age":29,"tenure_months":3,"monthly_charge":130,"total_charge":390,
 "contract_type":"按月付费","payment_method":"电子支票","support_calls":9,"is_active":0}
```

预期返回（实测）：

```json
{"churn":1,"probability":0.9199,"risk_level":"高"}
```

3. 最后打开 <http://localhost:8501>，拖滑块看概率实时变化

> 话术：“模型已经不是硬盘上的文件，而是一个在线服务，任何系统都能调——这就是‘部署’。”

## 四、专项二：大数据应用开发（约 1.5 分钟）

### 4.1 Spark 数据清洗 —— `courses/02-bigdata/01-Spark数据清洗.ipynb`

**第一格要等 20～30 秒**（起 JVM），不是卡死。

| 小节 | 演什么 | 讲解要点 |
|---|---|---|
| 1. 读取原始数据 | `spark.read.csv(..., encoding='UTF-8')` | CSV 带 BOM，第一列名有隐藏字符，要先清掉 |
| 2. 清洗 | `cast` + `when/otherwise` | **Spark 的 `cast` 转不了就返回 null**，等价于 pandas 的 `coerce` |
| 3. 异常值 + 去重 | `filter` + `dropDuplicates` | 同一条业务规则，换成分布式写法 |
| 4. 衍生特征 | `withColumn` | 和 pandas 的列运算一一对应 |
| 5. 写出 Parquet | `write.parquet` | 列式存储，下游 SparkML 直接用 |

**核心演示点（务必做）**：

1. 跑完 `filter` / `withColumn` 后说：**“注意，这些还没真正计算，只是建了执行计划”**
2. 立刻跑 `df.count()` 触发计算
3. 打开 <http://localhost:4040>，指三样东西：
   - **DAG 图**（这一串算子的血缘）
   - **Stage 划分**（哪里发生 shuffle）
   - **Shuffle Read/Write 量**（数据在网络间搬了多少）

> 话术：“这是分布式作业的体检报告。pandas 里你只能看到‘跑了 3 秒’，看不到它内部怎么拆、哪里在搬数据、瓶颈在哪。”

### 4.2 Spark MLlib 训练 —— `02-SparkML训练.ipynb`

`Pipeline` 串起「特征处理 → 分类器」，训练两个模型并打印 AUC，最后 `save` 整个 Pipeline。

> 话术：“和 sklearn 的 Pipeline 是同一个思想：把预处理和模型打包成一个对象，避免训练/推理不一致。”

## 五、专项三：大模型应用开发（约 1.5 分钟）

### 5.1 页面演示（推荐先看效果）—— <http://localhost:8502>

**侧栏没有 Key 输入框，只有一个开关。打开页面直接点示例就行：**

| 控件 | 默认值 | 说明 |
|---|---|---|
| 启用大模型回答 | 开 | 开 = 调模型出答案；**关 = 只展示拼好的 prompt**（讲 RAG 两段结构用） |
| Base URL | `http://ollama:11434/v1` | 容器内的服务名，不是 localhost |
| 模型 | `qwen2.5-coder:1.5b` | 下拉框可直接输入其他模型名 |

> 本地模型不校验 Key，程序内固定用 `ollama`，界面上不再暴露。
> 想用云端模型：Base URL 改 `https://api.deepseek.com/v1`、模型选 `deepseek-chat`，
> 并在启动前设环境变量 `RAG_API_KEY=<你的 Key>`（`docker exec -e RAG_API_KEY=sk-xxx ...`）。

填错配置时页面会给明确提示，不会红屏：

| 现象 | 提示内容 |
|---|---|
| URL 写错（如 `.../vl`） | 「接口 404：… 本地模型请填 http://ollama:11434/v1」 |
| 连不上 | 「连不上 … 检查 Base URL（不是 localhost，也别漏 /v1）」 |
| Key 与地址不匹配 | 「鉴权失败（401）：Key 与 … 不匹配」 |
| 模型名不存在 | 「模型不存在：xxx」 |

1. 点示例问题「矩阵维度不匹配怎么排查」，等 5～10 秒出答案（1.5B 模型在本机约 7 秒）
2. 展开右侧**引用卡片**：命中 `PyTorch常见错误.md · 张量形状不匹配`，相似度约 0.195
3. 指一下答案末尾的「依据：xxx.md」，说明每条结论都能追溯到文件

> 话术：“答案是从这三份文档里**检索**出来的，不是模型凭记忆编的。每句话都能追溯到某个文件——这是 RAG 和直接问大模型的本质区别。”

> 话术：“答案是从这三份文档里**检索**出来的，不是模型凭记忆编的。每句话都能追溯到某个文件——这是 RAG 和直接问大模型的本质区别。”

### 5.2 链路拆解 —— `courses/03-llm-app/` 三个 notebook

| notebook | 演什么 | 讲解要点 |
|---|---|---|
| `01-文档切块与向量化` | 切块 → 向量化 → 检索 | 切块要按语义边界（标题/段落），不能硬切 500 字 |
| `02-RAG问答链路` | 检索 → 拼 prompt → 调用 → **对比不给资料的回答** | prompt 里三条硬约束：只依据资料、不知道就说不知道、必须列出处 |
| `03-Streamlit发布` | 启动页面 + 健康检查 | 和 8501 一样，从脚本到可访问的服务 |

`02` 里那一格「**对比：不给资料的模型会怎么答**」是整段的高光：同一问题，不给资料时模型会编，给了资料就会说“资料里没写”。

### 5.3 两种“没有云端 Key”的演法

**A. 用本地模型（默认，完全离线）**

开关打开，Base URL `http://ollama:11434/v1`，模型 `qwen2.5-coder:1.5b`——能出完整答案，只是语句比云端粗糙。这是“断网也能跑”的最好证据。

> 注意：1.5B 小模型偶尔会跳过正文只输出一行「依据：xxx」。代码里已加自动重试（结果短于 40 字就重试一次），实测 5 次全部出正文；万一还遇到，再点一次即可。

**B. 关掉开关，展示拼好的 prompt**

回答区会直接显示**准备发给大模型的完整 prompt**（没有任何多余说明文字），这反而是更好的讲解材料：

> “看，这就是送给大模型的东西：前半段是检索到的资料，后半段是问题和约束。RAG 的本质就是这两段——**检索负责事实，生成负责表达**。”

对比着演效果最好：先关开关看 prompt 结构，再打开让它真答出来。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| Notebook 报 `ModuleNotFoundError: pandas` | 内核选错 | 右上角切到 `python3`（venv 那个） |
| `FileNotFoundError: ../../data/raw/...` | 工作目录不对 | 用 8080 打开项目根目录后再开 notebook；不要单独拖文件打开 |
| Spark 第一格转圈半分钟 | 正在起 JVM | 正常，等它 |
| 4040 打不开 | Spark 会话没跑或已结束 | 重跑第一格；内核重启后端口会换（4041…） |
| MLflow 打开空白 | 不在项目根目录启动 | 用 `start.bat` 启动 |
| 卡片 04 显示“未启动” | 四个服务里至少一个挂了 | 看 `/tmp/*.log`，重启对应服务 |
| RAG 只出 prompt 不出答案 | 没配 Key | 设计如此，按 5.3 讲 |
