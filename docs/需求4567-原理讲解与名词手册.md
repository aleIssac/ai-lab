## 4.0 这条链路在做什么

整个实训是一条 AI 项目的标准流水线，学员从一张原始表格走到一个在线服务：


## 4.1 数据清洗的原理

### 原始数据有什么问题

拿到的 CSV 有 1545 行，问题不是"数据错"，而是"数据不规整"：

| 问题 | 表现 | 后果 |
|---|---|---|
| **类型污染** | 数值列里混了 `N/A`、`-`、空字符串 | pandas 把整列推断成 `object`（文本），后续无法计算 |
| **重复记录** | 同一个 `customer_id` 出现多次 | 训练集和测试集可能含同一条样本，指标虚高 |
| **缺失值** | 某些字段为空 | 大多数 sklearn 模型不接受 NaN |
| **类别不一致** | "按月付费" / "月付" / "Monthly" | one-hot 编码后会变成三个不同的特征 |

### 为什么类型推断会失败

CSV 没有类型信息，pandas 只能**猜**。它读一列时，如果全部能解析成数字，就判定为数值；
只要有一行是 `N/A`，整列退化成 `object`。这不是 bug，是设计如此——
因为 pandas 无法确定 `N/A` 到底是"缺失"还是"一个叫 N/A 的类别"。

**处理方式**：先显式声明 `na_values=['N/A', '-', '']`，再 `pd.to_numeric(col, errors='coerce')`，
把转不了的变成 NaN，然后统一填充（数值列用中位数、类别列用众数）。

### 为什么必须按 id 去重

这是初学者最容易忽略的一点。

假设 A 客户有三条记录，如果随机划分训练集和测试集，很可能两条进训练、一条进测试。
模型在训练时已经"见过"这个客户，测试时自然能猜对——指标看起来很好，但换成新客户就不行。

这叫做**数据泄漏（data leakage）**。正确做法是按 `customer_id` 分组划分，
保证同一个客户的所有记录只出现在一边。这份数据里重复了 45 行，去重后 1500 行。

### 名词

| 名词 | 解释 |
|---|---|
| **DataFrame** | pandas 的二维表格结构，有列名和行索引，类似 Excel 表 |
| **dtype / object** | pandas 的列类型。`object` 通常表示字符串，出现它往往意味着本该是数字的列被污染了 |
| **NaN** | Not a Number，缺失值的标准表示 |
| **缺失值填充（imputation）** | 用中位数、众数、均值等填补空缺，而不是直接删行 |
| **数据泄漏** | 训练时用到了预测时拿不到的信息（如同一样本同时出现在训练和测试集），导致评估结果虚高 |
| **去重（deduplication）** | 按业务主键删除重复记录 |

## 4.2 特征工程的原理

模型只认数字。所以"合同类型=按月付费"这种文字必须变成数字，而且不能简单编成 1、2、3——
那样模型会认为"3 比 1 大"，而类别之间本没有大小关系。

### One-Hot 编码

把一个类别列拆成若干个 0/1 列：

```
合同类型                 合同类型_月付  合同类型_一年  合同类型_两年
按月付费          →           1            0            0
一年                →         0            1            0
```

**代价**：维度膨胀。如果某列有 100 个类别，就多出 100 列。类别特别多时要用目标编码或嵌入。

### 标准化（Standardization）

把数值列变成"均值 0、标准差 1"：

```
x' = (x - 均值) / 标准差
```

**为什么需要**：不同特征的量纲差太远。`月费` 是几十到几百，`账龄` 是个位数。
梯度下降时，量纲大的特征会主导更新方向，收敛慢甚至震荡。标准化之后各特征"话语权"相当。

**注意**：标准化的均值和标准差必须**从训练集算出来**，然后应用到测试集和新数据。
如果用全量数据算，测试集的信息就泄漏进训练了。

### Pipeline 的意义

sklearn 的 `Pipeline` 把"预处理 + 模型"打包成一个对象：

```python
pipe = Pipeline([("prep", preprocessor), ("clf", LogisticRegression())])
pipe.fit(X_train, y_train)
```

好处有三个：

1. **不会漏步骤**——预测时自动走同样的预处理
2. **不会写反顺序**——训练和推理用完全一致的流程
3. **可以整体保存**——`joblib.dump(pipe)` 存下来，上线时直接加载

本项目为了能单独解释每一步，把预处理器和模型分别保存成两个 pkl，
但保证它们是一起训练、一起上线的。

### 名词

| 名词 | 解释 |
|---|---|
| **特征（feature）** | 输入模型的每一个维度，如年龄、月费 |
| **标签（label）** | 要预测的目标，这里是"是否流失"（0/1） |
| **One-Hot 编码** | 把类别转成互斥的 0/1 向量 |
| **标准化 / 归一化** | 标准化是减均值除标准差；归一化是缩放到 [0,1] 区间 |
| **Pipeline** | sklearn 的流水线，把多个处理步骤串联成一个整体 |
| **fit / transform / fit_transform** | `fit` 学习参数（如均值方差），`transform` 应用，`fit_transform` 两者合一 |
| **特征维度** | 特征的数量，本项目清洗后是二十多维（含 one-hot 展开） |

## 4.3 模型原理：逻辑回归与随机森林

### 逻辑回归（Logistic Regression）

名字里有"回归"，实际是**分类**模型。

原理：对特征做线性加权求和，再套一个 sigmoid 函数压到 0~1，输出就是"属于正类的概率"。

```
z = w₁x₁ + w₂x₂ + ... + b
p = 1 / (1 + e^(-z))
```

`sigmoid` 的作用是把任意实数映射到 (0,1)。`z` 越大，`p` 越接近 1。

**训练过程**：用梯度下降最小化交叉熵损失，也就是让预测概率尽量接近真实标签。

**C 参数是什么**：`C` 是正则化强度的**倒数**。C 越小，正则化越强，模型越保守。
本项目对比了 C=0.1 和 C=1.0——C=0.1 会压制权重，模型更简单，泛化可能更好。

**优点**：可解释。每个特征的权重 `w` 直接告诉你"这个特征增加 1 个单位，流失概率的 log-odds 变化多少"。
金融、医疗这类需要解释的场景首选。

**缺点**：只能拟合线性边界。特征之间如果有复杂的交互关系，它学不到。

### 决策树与随机森林（Random Forest）

**决策树**：不断选一个特征、选一个阈值，把数据切成两半，直到叶子节点足够纯。

```
月费 > 100 ?
├─ 是 → 客服通话次数 > 5 ?
│        ├─ 是 → 流失（高风险）
│        └─ 否 → 可能留存
└─ 否 → 通常留存
```

**单棵树的毛病**：容易过拟合。数据稍微变一点，树的结构可能完全不同。

**随机森林**：训练 200 棵树，每棵树用**不同的随机子集**（bootstrap 采样 + 随机选特征），
最后投票决定结果。

两个随机性是关键：
- **样本随机**：每棵树只看约 63% 的数据
- **特征随机**：每次分裂只在随机的一部分特征里选

这样 200 棵树的错误互相抵消，整体比任何一棵都稳。这叫 **bagging**（bootstrap aggregating）。

**优点**：能拟合非线性、对特征缩放不敏感、不容易过拟合。
**缺点**：不可解释（200 棵树没法直接看懂）、模型大、推理慢。

### 为什么 F1 和 AUC 会打架

本项目实测：

| 模型 | F1 | AUC |
|---|---|---|
| LogReg-C0.1 | 0.6569 | 0.9418 |
| LogReg-C1.0 | 0.6567 | 0.9429 |
| **RF-200** | **0.7121** | 0.9374 |

随机森林 F1 更高，但 AUC 更低。为什么？

**F1 依赖阈值**。默认阈值 0.5，模型输出概率 > 0.5 判为正类。
随机森林对少数类（流失客户）的召回率高（0.90），所以 F1 好看。

**AUC 与阈值无关**。它衡量的是"随机取一个正样本和一个负样本，模型给正样本打分更高的概率"。
逻辑回归虽然 F1 低，但整体排序能力略强。

**业务含义**：
- 如果目标是"尽量不漏掉可能流失的客户"，选随机森林
- 如果要做风险分层（前 10% 高、10-30% 中），逻辑回归的排序更可靠

这种"指标不一致"的讨论，比"跑通一个模型"有价值得多。

### 名词

| 名词 | 解释 |
|---|---|
| **分类 / 回归** | 分类预测离散类别（流失/不流失）；回归预测连续值（房价） |
| **二分类** | 只有两个类别。本项目是"流失/留存" |
| **sigmoid** | 把实数压到 (0,1) 的函数，逻辑回归的输出层 |
| **交叉熵（cross-entropy）** | 分类任务的损失函数，衡量预测概率分布与真实分布的差距 |
| **正则化（regularization）** | 在损失里加惩罚项，抑制参数过大，防止过拟合。L1 让权重稀疏，L2 让权重平滑 |
| **决策树** | 用一系列 if-else 规则做判断的模型 |
| **随机森林** | 多棵决策树投票，用样本和特征的双重随机性降低方差 |
| **bagging** | Bootstrap Aggregating，有放回采样训练多个模型再平均 |
| **过拟合 / 欠拟合** | 过拟合：训练集很好、测试集差；欠拟合：两边都差 |
| **精确率（precision）** | 判为正的样本里，真正是正的比例。"报的警有多少是真的" |
| **召回率（recall）** | 真正的正样本里，被找出来的比例。"该抓的抓到多少" |
| **F1** | 精确率和召回率的调和平均，两者兼顾 |
| **ROC / AUC** | ROC 是不同阈值下的（假阳率, 真阳率）曲线；AUC 是曲线下面积，越接近 1 越好，与阈值无关 |
| **混淆矩阵** | 真阳/假阳/真阴/假阴 四格统计表 |
| **超参数** | 训练前人为设定的参数（如 C、树的数量），不是模型学出来的 |
| **bootstrap** | 有放回抽样，每次抽 n 个样本，允许重复 |

## 4.4 实验追踪：MLflow 解决什么问题

### 痛点

机器学习实验天然是"组合爆炸"：

```
3 种模型 × 5 个学习率 × 2 种特征方案 × 2 种标准化方式 = 60 次实验
```

两周后你只记得"有个 0.71 的结果"，但完全想不起来是哪组参数、用的哪份数据、
模型文件存哪了。Excel 记不住，文件名也记不住。

### MLflow 的三个概念

| 概念 | 是什么 | 本项目 |
|---|---|---|
| **Experiment** | 一组相关实验的容器 | `churn-prediction` |
| **Run** | 一次训练执行 | `LogReg-C0.1` / `LogReg-C1.0` / `RandomForest-200` |
| **Artifact** | 产物文件 | `model.pkl`、`preprocessor.pkl`、混淆矩阵图 |

每次 `run` 记录三类东西：

1. **参数（params）**：`C=0.1`、`n_estimators=200`、`max_depth=None`
2. **指标（metrics）**：`f1=0.6569`、`roc_auc=0.9418`、`accuracy=0.8433`
3. **产物（artifacts）**：模型文件、图片、任意文件

### 为什么存两个 pkl

这是本项目特意设计的教学点：

```
model.pkl          ← 模型权重
preprocessor.pkl   ← 标准化参数、one-hot 编码表
```

**如果只更新模型不更新预处理**：预测不会报错，但结果是错的。
比如训练时"月费"用均值 65 标准化，上线时预处理换成新版本用均值 80，
模型收到的输入分布就变了，输出全是垃圾——而且**没有任何异常提示**。

这是线上事故最常见的来源之一。MLflow 把两个都当产物存，就是为了保证配套。

### 名词

| 名词 | 解释 |
|---|---|
| **实验追踪（experiment tracking）** | 记录每次训练的参数、指标、产物，便于复现和比较 |
| **Run** | 一次完整的训练执行 |
| **Artifact** | 训练产生的文件（模型、图表、数据集快照） |
| **可复现性** | 给定参数和数据，能重现同样的结果 |
| **基线（baseline）** | 最简单的对照模型，用来衡量改进是否有效 |

## 4.5 服务化的原理

### 从文件到接口

训练完的模型是个 pkl 文件，只有 Python 能读。要让前端、小程序、教务系统都能用，
必须包成 HTTP 接口。

```
训练脚本  →  model.pkl     （离线，一次性）
               ↓ 加载
FastAPI   →  POST /predict  （在线，常驻）
               ↓
业务系统  →  {"churn":1,"probability":0.9199,"risk_level":"高"}
```

### 为什么用 FastAPI

| 特性 | 好处 |
|---|---|
| 自动生成文档 | 打开 `/docs` 就是可交互的 Swagger 页面，验收时能直接点 |
| Pydantic 校验 | 请求字段类型、范围自动校验，缺字段直接返回 422 而不是崩溃 |
| 异步支持 | 高并发时不会一个请求堵住所有 |
| 性能 | 基于 Starlette + uvicorn，比 Flask 快 |

### 接口设计的三件事

**输入模型**（Pydantic）：

```python
class Customer(BaseModel):
    age: int
    tenure_months: int
    monthly_charge: float
    contract_type: str
    ...
```

**预处理一致性**：接口内部先 `preprocessor.transform()` 再 `model.predict_proba()`，
和训练时完全同一条路。

**输出语义**：不只返回 0/1，还返回概率和风险等级。
业务方需要知道"有多可能"，而不只是"是不是"。

实测返回：

```json
{"churn":1,"probability":0.9199,"risk_level":"高"}
```

### 名词

| 名词 | 解释 |
|---|---|
| **REST API** | 用 HTTP 方法（GET/POST）操作资源的接口风格 |
| **FastAPI** | Python 的现代 Web 框架，自带文档和类型校验 |
| **Pydantic** | 数据校验库，定义请求/响应的结构 |
| **uvicorn** | ASGI 服务器，跑 FastAPI 的进程 |
| **序列化（serialization）** | 把对象存成文件或字节流，pkl 是 Python 的一种 |
| **推理（inference）** | 用训练好的模型做预测 |
| **延迟（latency）/ 吞吐（throughput）** | 单次响应时间 / 单位时间能处理的请求数 |

## 4.6 RAG 的原理（这一节是重点）

### 为什么需要 RAG

直接问大模型"我们课程里矩阵维度不匹配怎么讲"，它会编——因为训练数据里没有我们的讲义。

它的本质是**概率续写**：根据前文预测下一个最可能的词。没有外部信息时，
它会生成"看起来合理"的内容，这在事实性问题上就是幻觉（hallucination）。

**RAG 的思路**：先从我方文档里找到相关内容，把原文塞进提示词，让模型**照着资料回答**。

```
不用 RAG：问题 → 模型（凭记忆） → 可能编造
用 RAG：  问题 → 检索 → 资料 → 模型（照资料） → 有出处
```

### 第一步：切块（chunking）

为什么不能整篇喂进去：

1. 上下文窗口有限（虽然现在很大，但塞满会稀释注意力）
2. 检索粒度太粗——整篇丢进去，模型不知道哪一段有用
3. 相似度计算会失真——整篇的平均向量什么都像又什么都不像

**正确的切法**是按语义边界切。本项目按 Markdown 标题切：

```
## 张量形状不匹配        ← 一个块
正文...

## 设备不一致            ← 另一个块
正文...
```

每块带上标题作为元数据。这样检索命中的时候，你既拿到正文，也知道它属于哪个主题。

硬切 500 字的问题：可能把"错误现象"和"解决方法"切到两个块里，
检索到前一半，答案就只有问题没有解法。

**本项目结果**：3 篇文档 → 16 个片段。

### 第二步：向量化（vectorization）

要把"语义相似"变成"可以计算的数字"，就得把文本变成向量。

#### 本项目的做法：TF-IDF + 字符 n-gram

**TF-IDF**（词频 - 逆文档频率）：

```
TF  = 某个词在这篇文档里出现的次数 / 这篇文档的总词数
IDF = log(总文档数 / 包含这个词的文档数)
权重 = TF × IDF
```

直觉：一个词在这篇文档里出现得多（TF 高），但在所有文档里都少见（IDF 高），
说明它对这个文档有辨识度，权重应该大。

"的""是""在"这类词到处都有，IDF 接近 0，自动被压掉——这就是它不需要额外去停用词的原因。

**char_wb + (2,3) 是什么意思**：

```python
TfidfVectorizer(analyzer="char_wb", ngram_range=(2, 3))
```

- `char_wb`：按字符切，但只在词边界内（word boundary）
- `(2,3)`：取 2 个字符和 3 个字符的组合

"矩阵" → `矩阵`（2-gram）；"维度不匹配" → `维度`、`度不`、`不匹`、`匹配`、`维度不`、`度不匹`…

**为什么用字符而不是词**：

1. 中文不需要分词，避免分词错误带来的连锁问题
2. 对代码术语友好：`RuntimeError`、`reshape`、`mat1` 这些词词典里没有，但字符级能匹配上
3. 抗错别字：`矩阵` 和 `矩证` 有 1 个字符重合，仍有一定相似度

**为什么不用 bge 这类语义嵌入模型**：

1. **离线环境没有模型文件**——bge 最小也有几百 MB，还要额外的推理依赖
2. **规模不需要**——16 个片段，TF-IDF 的排序已经够准
3. **可解释**——TF-IDF 能说清楚"为什么这两段像"，语义向量说不清

**代价**：TF-IDF 只认字面重合，不认同义。
问"维度对不上"和文档里的"形状不匹配"，字面几乎不重合，可能检索不到。
生产环境换 bge 就能解决，代码里 `KnowledgeBase` 封装了接口，换实现不用改调用方。

**本项目实测**：词汇表维度 5071。

### 第三步：检索

把问题也转成同维度的向量，然后算**余弦相似度**：

```
cos(A,B) = (A·B) / (|A| × |B|)
```

只看方向不看长度——一段长文本和一段短文本讲同一件事，向量方向接近，余弦值就高。

取 top-3 作为上下文。

**为什么是 3 不是 10**：
- 太多会稀释——真正相关的可能就 1~2 条，其余是噪声
- 上下文越长，模型越容易"看串"
- 模型窗口有限，塞太多不一定是好事

本项目实测：问"矩阵维度不匹配怎么排查"，
top1 命中《PyTorch常见错误·张量形状不匹配》，相似度 0.195。

0.195 这个数值看起来低，但 TF-IDF 的绝对值本来就不高（没有语义泛化），
**看排序不看绝对值**——第一名是对的就行。

### 第四步：拼 prompt

```text
[system]
你是 AI 实训平台的助教。请严格依据用户给出的资料回答问题：
1. 只使用资料中的信息，资料里没有的内容不要补充，不要编造；
2. 资料不足时也要先回答资料里已有的部分，不要只回一句结论；
3. 先分条写排查步骤或做法，最后单独一行用「依据：」列出引用的来源文件名。

[user]
[资料1] 来源：PyTorch常见错误.md · 张量形状不匹配
正文...

[资料2] 来源：深度学习基础.md · 过拟合与正则化
正文...

[资料3] ...

问题：矩阵维度不匹配怎么排查
```

**为什么规则要放 system**：这是踩坑得来的。

一开始把规则和资料塞在同一条 user 消息里，结果 1.5B 模型把规则末尾的「依据：」
当成了唯一要输出的东西，只回一行"依据：PyTorch常见错误.md"，正文一个字不写。

改成 system / user 分离后，模型能正确区分"这是规则"和"这是素材"，正文正常输出。

**第 2 条规则也改过**：原话是"资料不足以回答就直接说明「资料中没有相关说明」"。
结果模型看到资料不太相关，就直接回一句"资料中没有"，把能答的部分也跳过了。
改成"资料不足也要先答已有的部分"，才正常。

### 第五步：生成

本地 qwen2.5-coder:1.5b 读 prompt，输出答案。

**小模型的局限**：
- 语句组织能力弱，答案可能啰嗦或跳跃
- 偶尔会漏掉「依据」那一行
- 实测三个问题里有一个会退化（只输出一行依据），所以代码里加了兜底：结果短于 40 字就重试一次

**但核心价值不受影响**：答案来自检索到的资料，不是模型凭记忆编的。
这对教学场景已经够用——学生要的是"这个问题该查哪份文档"，而不是一篇漂亮文章。

### 名词

| 名词 | 解释 |
|---|---|
| **RAG** | Retrieval-Augmented Generation，检索增强生成：先检索资料，再让模型基于资料回答 |
| **幻觉（hallucination）** | 模型生成看起来合理但事实错误的内容 |
| **切块（chunking）** | 把长文档切成小片段，便于检索 |
| **向量化 / 嵌入（embedding）** | 把文本转成数值向量，语义相近的向量距离近 |
| **TF-IDF** | 词频 × 逆文档频率，衡量词对文档的辨识度 |
| **n-gram** | 连续的 n 个字符或词。2-gram 就是相邻两字 |
| **char_wb** | sklearn 的字符级分析模式，只在词边界内切 n-gram |
| **余弦相似度** | 两个向量夹角的余弦值，看方向不看长度，范围 [-1,1] |
| **top-k 检索** | 取相似度最高的 k 个片段 |
| **上下文（context）** | 塞进 prompt 里给模型看的资料 |
| **prompt** | 发给模型的完整输入，包含规则、资料、问题 |
| **system / user 消息** | 对话接口的两种角色：system 放规则设定，user 放具体任务 |
| **上下文窗口** | 模型一次能处理的最大 token 数 |

## 4.7 项目讲解：这条线怎么讲给学员

### 讲解顺序（建议）

| 顺序 | 讲什么 | 关键提问 |
|---|---|---|
| 1 | 先看数据（脏在哪） | "为什么这列是 object？" |
| 2 | 清洗（去重、填充） | "如果不去重，指标会怎样？" |
| 3 | 特征工程 | "为什么不能把类别编成 1/2/3？" |
| 4 | 训练三个模型 | "F1 高的就一定好吗？" |
| 5 | 看 MLflow | "两周后你怎么找回最好那次？" |
| 6 | 上线 | "为什么存两个 pkl？" |
| 7 | RAG | "模型的答案凭什么可信？" |

### 三个必须让学员自己得出的结论

1. **指标不是越高越好**，要看业务目标（召回优先还是排序优先）
2. **预处理和模型必须配套**，这是隐形事故的来源
3. **答案的可追溯性比答案本身重要**，这是 RAG 的核心价值

### 常见学员误区

| 误区 | 纠正 |
|---|---|
| 先划分训练测试集，再去重 | 必须先清洗再去重，否则测试集里可能有训练样本 |
| 用全量数据算标准化参数 | 只能用训练集算，否则信息泄漏 |
| 只看 accuracy | 不平衡数据下 accuracy 会骗人（全判"不流失"也有 84%） |
| 认为 RAG 就是"加个知识库" | 核心在检索质量和 prompt 约束，不是有没有库 |

# 第二部分 需求⑤ 神经网络超参实验

## 5.1 这个页面到底是什么

**底层是 TensorFlow Playground 的实现**——Google Brain 团队 2016 年做的教学工具。

它的关键特点是：**训练是真的**。

不是播放一段预录的动画，而是浏览器里真的在算：
- 前向传播：输入 → 隐藏层 → 输出
- 损失计算
- 反向传播：算每个权重的梯度
- 梯度下降：更新权重

用的库是团队自己写的 `nn.ts`（TypeScript 的极简神经网络实现），
后来演化成 deeplearn.js，再演化成今天的 TensorFlow.js。

**为什么这很重要**：如果是动画，改参数不会有真实变化；因为是真算，
"加一层"和"不加"的结果真的不一样——这才有教学价值。

---

## 5.2 前向传播

一个神经元做的事：

```
z = w₁x₁ + w₂x₂ + ... + wₙxₙ + b      （加权求和）
a = activation(z)                      （过激活函数）
```

- `w` 是权重，`b` 是偏置
- `activation` 是激活函数（ReLU / Tanh / Sigmoid / 线性）

一层里有多个神经元，每个都有自己的权重，全部并行算一遍。

**网络结构**：输入层 → 若干隐藏层 → 输出层。

本项目页面里可调：
- 隐藏层数量（0~6 层）
- 每层神经元数量（1~8 个）

一个有 2 个隐藏层、每层 4 个神经元的网络，参数量大约是：
`(2×4+4) + (4×4+4) + (4×1+1) = 12 + 20 + 5 = 37 个参数`。

---

## 5.3 损失、梯度与反向传播

### 损失函数

模型输出和真实标签的差距。

**分类**：交叉熵
```
L = -[y·log(p) + (1-y)·log(1-p)]
```
预测对了损失小，预测错了损失大，且错得越离谱惩罚越重。

**回归**：均方误差
```
L = (y - ŷ)²
```

### 梯度下降

知道损失之后，要让损失变小，就得知道"往哪个方向调权重"。
这个方向就是**梯度**——损失对每个权重的偏导数。

```
w_new = w_old - learning_rate × ∂L/∂w
```

- `∂L/∂w` 告诉你"w 增大一点，损失会怎么变"
- 负号表示往反方向走（下坡）
- `learning_rate` 是步长

### 反向传播

问题：一个 6 层网络有几百个权重，怎么高效算出每个权重的梯度？

答案是**链式法则**：从输出层往回算，每层的梯度用后一层的梯度乘上本层的导数。
这样一次前向 + 一次反向，就能算出所有梯度，复杂度只比前向传播多一倍。

这就是深度学习能跑起来的关键——没有反向传播，几百万参数根本没法训练。

### 学习率的影响

| 学习率 | 现象 |
|---|---|
| 太小（0.001） | 损失下降极慢，几百轮还没收敛 |
| 合适（0.03） | 平稳下降 |
| 太大（1.0） | 损失震荡甚至发散，边界乱跳 |

在页面上拖学习率滑块能直接看到这个现象——这是黑板讲不清的。

---

## 5.4 各个超参的作用

### 隐藏层数量（depth）

- **0 层**：只能画直线（线性分类器）
- **1 层**：能画曲线，简单的非线性问题
- **2~4 层**：能画复杂的封闭区域、螺旋

**教学示范**：用"螺旋数据集"，0 层和 1 层都分不开，2 层能分开。
这一下就把"深度有什么用"讲明白了。

### 每层神经元数量（width）

神经元越多，能表达的模式越复杂，但也越容易过拟合。

页面右上角有个"参数量"提示，改神经元数能看到参数暴涨——
讲"为什么大模型贵"可以从这里切入。

### 激活函数

| 激活函数 | 形状 | 特点 |
|---|---|---|
| **线性** | y = x | 无论多少层，叠加起来还是线性，等于白加层 |
| **ReLU** | max(0, x) | 最常用，计算快，正区间梯度恒为 1，缓解梯度消失 |
| **Tanh** | (−1,1) | 输出有界，中心对称，收敛快 |
| **Sigmoid** | (0,1) | 老派选择，两端饱和导致梯度消失，深层网络慎用 |

**教学示范**：把激活函数切到"线性"，再增加层数——决策边界还是直线。
这是"为什么需要非线性激活"最直接的证据。

### 正则化

在损失里加惩罚项，抑制权重过大：

```
L_total = L + λ × (权重的某种范数)
```

| 类型 | 惩罚项 | 效果 |
|---|---|---|
| **L1** | Σ\|w\| | 让部分权重变成 0，产生稀疏解（相当于自动选特征） |
| **L2** | Σw² | 让权重整体变小变平滑，最常用 |

`λ`（页面上的"正则化强度"）越大，惩罚越重，模型越保守。

**教学示范**：把正则化调到最大，边界变得非常平滑，连训练点都分不开——欠拟合。
调到 0，边界贴着每个噪声点扭曲——过拟合。

### 批次大小（batch size）

一次梯度更新用多少个样本。

- **小 batch（1~10）**：更新频繁，噪声大，可能跳出局部极小，但慢
- **大 batch（50+）**：更新平滑，稳定，但可能卡在平坦区域

### 数据集与噪声

- **数据集**：圆形、异或（XOR）、高斯、螺旋。每种考验不同的表达能力
- **噪声**：给标签随机翻转。噪声高时，过度复杂的模型会把噪声也学进去（过拟合的直观展示）
- **训练/测试比例**：影响评估的可信度

---

## 5.5 决策边界是怎么画出来的

页面右侧那片彩色区域不是模型"想出来的"，是这样算的：

1. 在整个画布上铺一张网格（比如 100×100 个点）
2. 把每个网格点当作输入，跑一次前向传播，得到一个输出值
3. 按输出值给这个点上色（蓝/橙，深浅表示置信度）

100×100 = 一万次前向传播，每帧都算一遍。所以层数越多、神经元越多，页面越卡——
这也是"推理成本"的直观体验。

| 名词 | 解释 |
|---|---|
| **神经元（neuron / unit）** | 网络的基本单元，做加权求和 + 激活 |
| **权重（weight）/ 偏置（bias）** | 神经元的可学习参数 |

| **学习率（learning rate）** | 每次更新的步长 |

| **ReLU** | max(0,x)，最常用的激活函数 |

| **正则化** | 抑制参数过大、防止过拟合的手段 |
| **L1 / L2** | 两种正则化范数，前者稀疏、后者平滑 |
| **决策边界** | 分类器把空间分成两类的分界线 |
| **参数量** | 网络中所有权重和偏置的总数 |
| **超参数** | 训练前人为设定、不由训练学出的参数 |

# 第三部分 需求⑥ Transformer 可视化

## 6.1 Transformer 是什么

2017 年论文《Attention Is All You Need》提出，现在是所有大语言模型的基础架构
（GPT、BERT、LLaMA、Qwen 都是它的变体）。

**它要解决的问题**：之前的模型（RNN/LSTM）必须按顺序一个词一个词处理，
不能并行，长距离依赖也容易丢。Transformer 用**注意力机制**让所有词同时互相"看"，
既并行又能捕捉远距离关系。

**GPT 这类模型做的是什么**：给定前文，预测下一个 token。
把预测出的 token 接到末尾，再预测下一个，循环下去就生成了一整段话。

---

## 6.2 Tokenization：文本怎么变成模型能吃的数字

### 为什么不能按字或按词切

- **按字**：中文还好，英文 `unbelievable` 会被切成 12 个字母，序列太长
- **按词**：词表爆炸（英文几十万词），而且遇到没见过的词就没法处理（OOV 问题）

### BPE（Byte Pair Encoding）

折中方案：**子词（subword）**。

训练过程：
1. 初始词表是所有单个字符
2. 统计语料里出现最频繁的相邻字符对，合并成一个新单元
3. 重复几万次，得到一个大词表（GPT-2 是 50257 个）

效果：

```
"low"        → low
"lower"      → low + er
"empowers"   → em + powers      ← 词表里没有整词，被拆成两段
"unbelievable" → un + believ + able
```

**这就是为什么**模型对罕见词和错别字敏感——它看到的是碎片，语义会失真。

本项目页面上，输入 `Data visualization empowers us to` 被切成 6 个 token，
其中 `empowers` 显示为 `em` + `powers`，正是 BPE 的效果。

### 名词

| 名词 | 解释 |
|---|---|
| **token** | 模型处理的最小单位，可能是一个字、一个词或词的一部分 |
| **词表（vocabulary）** | 所有 token 的集合，GPT-2 是 50257 个 |
| **BPE** | Byte Pair Encoding，按频率合并字符对的子词切分算法 |
| **OOV** | Out of Vocabulary，词表外的词，BPE 用子词切分缓解了这个问题 |

---

## 6.3 Embedding 与位置编码

### Token Embedding

每个 token 查表得到一个向量。GPT-2 small 的维度是 **768**。

为什么是向量而不是编号：编号没有语义关系（"猫"=1、"狗"=2，模型会以为狗比猫大）。
向量空间里，语义相近的词距离近：

```
vec("猫") - vec("小猫") ≈ vec("狗") - vec("小狗")
```

这个性质叫**词向量的线性关系**，是 word2vec 时代就发现的。

### 位置编码（Positional Encoding）

**问题**：注意力机制本身是"无序"的——把所有词打乱，算出来的结果一样。
但"狗咬人"和"人咬狗"意思完全不同。

**解决**：给每个位置加一个独特的向量。

原始论文用正弦函数：

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```

用正弦而不是简单的 0,1,2,3，是因为：
- 数值有界，不会随位置增长而爆炸
- 不同位置之间可以通过线性变换互相表示，模型容易学到"相对位置"

最后把 token 向量和位置向量**相加**，得到最终输入。

### 名词

| 名词 | 解释 |
|---|---|
| **Embedding** | 把离散的 token 映射成稠密向量 |
| **嵌入维度（d_model）** | 向量的长度，GPT-2 small 是 768 |
| **位置编码** | 给每个位置一个向量，让模型知道词的顺序 |
| **token 向量 / 隐状态** | 每个位置在每一层的 768 维表示 |

## 6.4 自注意力：核心机制

### 一句话概括

每个词问一句"我该关注谁"，然后按关注度把别人的信息加权取过来。

### Q、K、V 是什么

每个 token 的向量会经过三个不同的线性变换，得到三个新向量：

| 名称 | 类比 | 作用 |
|---|---|---|
| **Query（查询）** | 我在找什么 | 当前词的"需求" |
| **Key（键）** | 我是什么 | 每个词的"标签" |
| **Value（值）** | 我有什么内容 | 每个词的"实际信息" |

**图书馆类比**：
- Query 是你的检索需求
- Key 是书脊上的标签
- Value 是书里的内容

你拿需求去比对所有标签（Q·K），匹配度高的书，就把它的内容（V）多取一点。

### 计算过程

**第一步：打分**

```
score(i,j) = Qᵢ · Kⱼ
```

当前词 i 的 Query 和每个词 j 的 Key 做点积。点积越大，说明方向越一致，相关性越高。

**第二步：缩放**

```
score / √d_k
```

`d_k` 是每个头的维度（GPT-2 small 是 768/12 = 64）。
除以 √64 = 8，是因为点积的方差会随维度增长——不缩放的话，
softmax 会变得极端（几乎全部分配给一个词），梯度趋近于 0，训练不动。

**第三步：掩码（Mask）**

生成式模型必须保证"不能看未来"。所以在 softmax 之前，把当前位置之后的所有分数设为 -∞：

```
        Data  visu  em  powers  us  to
Data  [  ✓     ✗    ✗    ✗     ✗   ✗ ]
visu  [  ✓     ✓    ✗    ✗     ✗   ✗ ]
em    [  ✓     ✓    ✓    ✗     ✗   ✗ ]
```

这就是**因果掩码（causal mask）**，画出来是下三角。
这也是为什么可视化页面里的注意力矩阵是三角形——不是画错了。

**第四步：Softmax**

把分数变成概率分布（每行加起来等于 1）。

```
attn(i,j) = softmax(score(i,j) / √d_k)
```

**第五步：加权求和**

```
outputᵢ = Σⱼ attn(i,j) × Vⱼ
```

当前词的输出 = 所有词的 Value 按注意力权重加权平均。

### 多头（Multi-Head）

GPT-2 small 有 **12 个头**，每个头独立做上面这套计算，最后把 12 个结果拼接起来再线性变换一次。

**为什么要多头**：不同的头能学到不同的模式。

| 头的类型 | 关注什么 |
|---|---|
| 语法头 | 主谓一致、介词搭配 |
| 指代头 | "它"指的是前面哪个名词 |
| 位置头 | 相邻的几个词 |
| 语义头 | 主题相关的词 |

单头只能学一种关系，多头能同时捕捉多种。

可视化页面里可以逐个切换头，看到关注的模式确实不一样。

### 名词

| 名词 | 解释 |
|---|---|
| **注意力（attention）** | 按相关性给不同位置分配权重的机制 |
| **自注意力（self-attention）** | Query、Key、Value 都来自同一个序列 |
| **Q / K / V** | 查询、键、值，三个线性变换后的向量 |
| **点积（dot product）** | 两个向量对应位置相乘再求和，衡量方向一致性 |
| **缩放（scaling）** | 除以 √d_k，防止 softmax 饱和 |
| **softmax** | 把一组实数变成概率分布（非负、和为1） |
| **多头（multi-head）** | 并行多组注意力，各关注不同模式 |
| **因果掩码（causal mask）** | 遮住未来位置，保证只能看前文 |
| **注意力权重矩阵** | 形状为 (序列长度 × 序列长度) 的权重表，可视化里的热力图 |

## 6.5 残差连接与层归一化

### 残差连接（Residual Connection）

```
output = x + sublayer(x)
```

把输入直接加到子层的输出上。

**为什么需要**：深层网络有梯度消失问题——反向传播时梯度每层都乘一次导数，
层数多了梯度就趋近 0，前面的层学不动。

残差连接提供了一条"高速公路"：梯度可以直接跳过子层回传。这样几十层也能训练。

可视化页面里那条绕过注意力和 MLP 的灰色弧线，就是残差。

### 层归一化（Layer Normalization）

对每个 token 的 768 维向量做归一化（减均值、除标准差），再乘一个可学习的缩放、加一个偏移。

**作用**：稳定训练。不同层的数值范围差异很大，归一化之后每层输入分布稳定，
学习率可以设大一些，收敛更快。

**和 BatchNorm 的区别**：BatchNorm 是在 batch 维度上算统计量，
LayerNorm 是在单个样本的特征维度上算——不依赖 batch 大小，适合变长序列。

### 名词

| 名词 | 解释 |
|---|---|
| **残差连接（skip connection）** | 把输入直接加到输出上，缓解深层网络梯度消失 |
| **层归一化（LayerNorm）** | 对单个样本的特征维度做归一化 |
| **梯度消失** | 反向传播时梯度逐层衰减到接近 0，浅层无法更新 |

## 6.6 前馈网络（MLP）

注意力之后还有一个两层全连接：

```
768 → 3072 → 768
```

中间夹一个 **GELU** 激活函数（ReLU 的平滑版本）。

**作用**：注意力负责"在位置之间搬运信息"，MLP 负责"对每个位置单独做变换"。
两者交替，前者的输出是后者的输入。

**关键区别**：MLP 不跨 token。它只看当前这一个位置的 768 维向量，
升维到 3072 再降回来。所以模型的知识大部分存在 MLP 的权重里
（这也是"模型参数量的三分之二在 MLP"这个说法的来源）。

### 名词

| 名词 | 解释 |
|---|---|
| **MLP / FFN** | 多层感知机 / 前馈网络，两层全连接 + 激活 |
| **GELU** | 高斯误差线性单元，ReLU 的平滑版本，GPT 系列常用 |
| **隐层维度（d_ff）** | MLP 中间层的宽度，GPT-2 small 是 3072 |

## 6.7 输出层与采样

### 从隐状态到词表概率

最后一层的输出（768 维）经过一个线性层映射到词表大小（50257 维），得到 **logits**。

logits 是没归一化的分数，可以任意大或小。用 softmax 变成概率：

```
p(token) = softmax(logits)
```

### 采样策略

| 方法 | 做法 | 效果 |
|---|---|---|
| **贪心（greedy）** | 永远选概率最高的 | 确定但重复，容易陷入循环 |
| **温度（temperature）** | logits 先除以 T 再 softmax | T<1 更保守，T>1 更发散 |
| **top-k** | 只在概率最高的 k 个里采样 | 砍掉长尾的胡话 |
| **top-p（核采样）** | 取累积概率达到 p 的最小集合 | 自适应候选数量，比 top-k 更灵活 |

**温度的原理**：

```
p = softmax(logits / T)
```

T=0.8 时，高分词的相对优势被放大，输出更确定；
T=1.5 时，分布被拉平，低概率词也有机会被选中，输出更多样但更容易跑偏。

本项目页面默认 T=0.8、top-k=5，所以概率榜上 `visualize 21.15%`、`see 12.26%` 这些
是**经过温度缩放后**的概率。

### 名词

| 名词 | 解释 |
|---|---|
| **logit** | softmax 之前的原始分数，未归一化 |
| **softmax** | 把 logits 变成概率分布 |
| **贪心解码** | 每步选概率最高的 token |
| **温度（temperature）** | 控制输出随机性的参数 |
| **top-k 采样** | 只在最高的 k 个候选里采样 |
| **top-p / 核采样** | 在累积概率达到 p 的候选集合里采样 |
| **生成（generation）** | 逐 token 预测并拼接的过程 |

# 第四部分 需求⑦ 经典算法可视化

## 7.1 卷积神经网络（CNN）

### 为什么需要卷积

全连接网络处理图像有两个致命问题：

1. **参数量爆炸**：一张 224×224×3 的图，接一个 1000 个神经元的全连接层，
   参数量 = 224×224×3×1000 ≈ 1.5 亿
2. **丢失空间结构**：把图像拉平成一维，"左上角的猫耳朵"和"右下角的猫尾巴"关系就没了

### 卷积做什么

用一个小的**卷积核**（如 3×3）在图像上滑动，每个位置做加权求和：

```
输入 5×5，卷积核 3×3，步长 1
输出 3×3（每个位置是 9 个像素的加权和）
```

**三个关键性质**：

| 性质 | 含义 | 好处 |
|---|---|---|
| **局部连接** | 每个输出只看输入的一小块 | 参数量骤降 |
| **权重共享** | 同一个卷积核在整张图上滑动 | 一个核只需 9 个参数 |
| **平移不变性** | 猫在左上还是右下，同一个核都能检测到 | 泛化好 |

**卷积核学到什么**：浅层学到边缘、颜色块、纹理；深层学到部件（眼睛、轮子）和整体（猫脸、汽车）。

可视化页面里能看到每一层的卷积核图像——第一层通常是条纹和边缘，很符合直觉。

### 池化（Pooling）

**最大池化**：在一个小窗口里取最大值。

```
[1, 3]          输出 3
[2, 5]
```

作用：
- 降维，减少计算量
- 保留最强响应，提高对小幅位移的鲁棒性

### 典型 CNN 结构

```
输入图像
  → [卷积 → 激活 → 池化] × N    提取特征
  → 展平（Flatten）
  → 全连接层                     分类
  → Softmax                      输出概率
```

**本项目 MNIST 页面的真实结构**（从代码里读出来的）：

```
input    24×24×1          （28×28 随机裁剪 24×24，做数据增强）
conv     5×5×8,  relu
pool     2×2, stride 2
conv     5×5×16, relu
pool     3×3, stride 3
softmax  10 类
```

注意它是**卷积池化之后直接接 softmax**，没有全连接层——
这是较早期的做法（全卷积网络的思想），参数量更少。
现代 CNN 通常在最后加 1~2 层全连接。

### 名词

| 名词 | 解释 |
|---|---|
| **卷积（convolution）** | 用小核在输入上滑动做加权求和 |
| **卷积核 / 滤波器（kernel / filter）** | 那组可学习的权重，通常 3×3 或 5×5 |
| **特征图（feature map）** | 卷积的输出，每个通道是一张"响应图" |
| **步长（stride）** | 卷积核每次滑几格，步长 2 相当于降采样 |
| **填充（padding）** | 在边缘补 0，控制输出尺寸 |
| **池化（pooling）** | 在小窗口里取最大或平均，降维 |
| **展平（flatten）** | 把多维特征图拉成一维向量，接全连接层 |
| **感受野（receptive field）** | 输出上一个点，对应输入上多大的区域 |

## 7.2 自编码器（Autoencoder）

### 核心思想

**让网络学习"重建自己的输入"**。

```
输入 x → 编码器 → 瓶颈 z（低维） → 解码器 → 输出 x'
目标：让 x' 尽量接近 x
```

**为什么这有用**：中间那个瓶颈层维度很低（本项目默认只有 2 维），
网络被迫用很少的信息概括整张图。这个低维表示就是"压缩后的本质特征"。

### 训练目标

损失函数是重建误差：

```
L = ||x - x'||²
```

### 用途

| 用途 | 原理 |
|---|---|
| **降维** | 瓶颈层就是降维结果，比 PCA 能捕捉非线性结构 |
| **去噪** | 输入加噪声、目标用原图，网络学会"恢复" |
| **异常检测** | 训练数据重建得好，异常数据重建误差大 |
| **生成** | 在瓶颈空间采样再解码，能生成新样本（VAE 的思路） |

**本项目页面的真实结构**（28×28 手写数字）：

```
input       28×28 = 784 维
fc 50       tanh
fc 50       tanh
fc 2        ← 瓶颈层，只有 2 维
fc 50       tanh
fc 50       tanh
regression  784 维（重建输出）
```

784 维的图被压到 2 维再还原——相当于用两个数字概括一张手写数字图。
瓶颈层越窄，重建越模糊；把它改大，重建质量明显提升，这是"压缩率与信息保留"的直观演示。

页面左边原图、右边重建，训练中能看到图像从模糊逐渐清晰。
这也是**无监督学习**：全程没有用标签，目标就是输入本身。

### 名词

| 名词 | 解释 |
|---|---|
| **自编码器（autoencoder）** | 学习重建自身输入的神经网络 |
| **编码器 / 解码器** | 压缩部分 / 还原部分 |
| **瓶颈层（bottleneck）** | 维度最低的中间层，强迫网络提取本质特征 |
| **重建误差** | 输入和输出的差距，训练目标 |
| **无监督学习** | 不需要标签，只用输入本身 |

## 7.3 强化学习与 DQN

### 和 supervised learning 的区别

| | 监督学习 | 强化学习 |
|---|---|---|
| 数据 | 有标准答案（标签） | 没有标准答案，只有"奖励" |
| 反馈 | 立即、明确 | 延迟、稀疏 |
| 目标 | 预测准确 | 长期累计奖励最大 |

### 核心概念

**智能体（agent）** 在**环境（environment）** 里做**动作（action）**，
环境返回**状态（state）** 和**奖励（reward）**。

经典例子：杆子平衡（CartPole）——小车左右移动，让杆子不倒。
倒了一局结束，每撑一帧得 1 分。

### Q 值

**Q(s, a)** = 在状态 s 下做动作 a，之后能拿到的**累计奖励的期望**。

如果能准确知道 Q 值，策略就简单了：每个状态下选 Q 最大的动作。

### DQN（Deep Q-Network）

用神经网络来近似 Q 函数：输入状态，输出每个动作的 Q 值。

**两个关键技巧**：

| 技巧 | 解决什么问题 |
|---|---|
| **经验回放（experience replay）** | 连续的经验高度相关，直接训练会震荡。把经验存进缓冲区，随机采样训练 |
| **目标网络（target network）** | 训练时 Q 值一直在变，目标也在变，像"追自己的尾巴"。用一份延迟更新的网络算目标值 |

**训练过程**：

```
1. 用当前策略玩一局，把 (s, a, r, s') 存进缓冲区
2. 从缓冲区随机采样一批
3. 计算目标：y = r + γ × max Q_target(s', a')
4. 让 Q(s,a) 逼近 y
5. 每隔 N 步，把当前网络权重复制给目标网络
```

`γ`（折扣因子）表示"未来奖励打几折"。0.99 表示很看重长期回报。

本项目页面里的小车学习平衡，就是 DQN 的经典任务。
一开始乱动，几百轮之后学会"往倒的方向移"。

### 名词

| 名词 | 解释 |
|---|---|
| **强化学习（RL）** | 通过与环境交互、最大化累计奖励来学习策略 |
| **智能体（agent）** | 做决策的主体 |
| **状态（state）/ 动作（action）/ 奖励（reward）** | 强化学习的三要素 |
| **策略（policy）** | 从状态到动作的映射 |
| **Q 值（action-value）** | 在状态 s 下做动作 a 的长期回报期望 |
| **DQN** | 用深度神经网络近似 Q 函数的方法 |
| **经验回放** | 把历史经验存起来随机采样，打破数据相关性 |
| **目标网络** | 延迟更新的网络副本，提供稳定的训练目标 |
| **折扣因子 γ** | 未来奖励的衰减率 |

## 7.4 回归与分类

### 分类（classification）

输出是离散类别。二维分类演示里，红点和绿点是两类样本，
决策边界把平面分成两块。

**和神经网络超参实验的区别**：⑤ 是可以自选网络结构的通用实验台；
⑦ 的 classify2d 是固定结构、更轻量的演示，重点在"点击加点、边界实时变化"的交互。

### 回归（regression）

输出是连续值。

**一维回归**：给一个 x，预测 y 坐标。损失是均方误差。

**图像回归**：给一个坐标 (x, y)，预测该点的颜色 (r, g, b)。
训练完成相当于把整张图编码进了网络权重——有点像压缩，但没什么实用价值，
是个很好的"网络能拟合一切"的直观演示。

### 名词

| 名词 | 解释 |
|---|---|
| **分类** | 预测离散类别 |
| **回归** | 预测连续数值 |
| **决策边界** | 分类器划分空间的边界 |
| **均方误差（MSE）** | 回归的常用损失，预测值与真实值差的平方 |
| **拟合（fitting）** | 模型学习数据规律的过程 |

# 附录 术语总表

## 数据处理

| 术语 | 解释 |
|---|---|
| DataFrame | pandas 的二维表结构 |
| 缺失值 / NaN | 数据中的空值 |
| 去重 | 按主键删除重复记录 |
| 数据泄漏 | 训练时使用了预测时不可得的信息 |
| 特征工程 | 把原始数据转换成模型可用的数值特征 |
| One-Hot | 类别转 0/1 向量 |
| 标准化 | 减均值除标准差 |
| Pipeline | sklearn 的处理流水线 |

## 模型与评估

| 术语 | 解释 |
|---|---|
| 逻辑回归 | 线性加权 + sigmoid 的二分类模型 |
| 随机森林 | 多棵决策树 + 双重随机性的集成模型 |
| 决策树 | 一系列 if-else 规则 |
| 过拟合 / 欠拟合 | 训练集好测试集差 / 两边都差 |
| 正则化 | 抑制参数过大，防过拟合 |
| 精确率 / 召回率 / F1 | 报的准不准 / 该抓的抓到多少 / 两者调和平均 |
| ROC / AUC | 阈值无关的排序能力评估 |
| 交叉验证 | 把数据分成 k 折轮流验证，评估更稳 |

## 深度学习

| 术语 | 解释 |
|---|---|
| 前向传播 | 输入逐层算到输出 |
| 反向传播 | 从输出往回算梯度 |
| 梯度下降 | 按梯度反方向更新参数 |
| 学习率 | 更新步长 |
| 激活函数 | 引入非线性 |
| ReLU / GELU | 常用激活函数 |
| 损失函数 | 衡量预测误差 |

| 卷积 / 池化 | 提取局部特征 / 降维 |
| 自编码器 | 学习重建输入的模型 |
| 强化学习 / DQN | 通过奖励学习策略 / 用神经网络近似 Q 值 |

## 一页速记：四个需求各一句话

| 需求 | 一句话原理 |
|---|---|
| **④ 端到端实训** | 脏数据 → 清洗 → 特征工程 → 多模型对比 → 实验追踪 → 服务化；大模型专项用 RAG 把"凭记忆答"变成"照资料答" |
| **⑤ 超参实验** | 浏览器里真实训练，改层数/激活/学习率/正则化能直接看到决策边界怎么变 |
| **⑥ Transformer** | token → 向量 + 位置编码 → 12 层（多头注意力 + MLP，各带残差和归一化）→ logits → 概率 → 采样 |
| **⑦ 经典算法** | 卷积提特征、自编码器学压缩、DQN 靠奖励学策略，全部在浏览器里用 JS 真实计算 |
