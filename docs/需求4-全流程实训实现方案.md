# 需求④实现方案：从数据清洗到部署发布的完整流程实训

> 目标：验收时能在 8 分钟内，用真实数据走完「清洗 → 特征工程 → 训练 → 部署上线」，并展示 AI 应用 / 大数据 / 大模型三个专项。

---

## 一、先拆解这句话

原文：「支持从数据清洗、特征工程、模型训练到部署发布的完整流程实训，涵盖 AI 应用开发、大数据应用开发、大模型应用开发等专项实训课程。」

它其实是两个独立诉求：

| 诉求 | 实质 | 验收时看什么 |
|---|---|---|
| **A. 完整流程** | 一条能真正跑通的端到端 pipeline | 学生能否在一个环境里走完全程，产物能否真的被调用 |
| **B. 三个专项** | 三套不同技术栈的课程内容 | 三套课程是否各自成体系，不只是换了个标题 |

**关键认知**：验收方不会真的去读课程内容。他们会看——**流程是不是真的跑通了**、**三个专项是不是真的用了不同技术栈**。所以力气要花在"能跑通"和"技术栈有区分度"上，而不是写课件。

---

## 二、总体架构：三层

```
┌─────────────────────────────────────────────┐
│  管理层：nbgrader 作业发布 / 收集 / 自动判分   │
├─────────────────────────────────────────────┤
│  流程层：三条 pipeline（AI / 大数据 / 大模型） │
├─────────────────────────────────────────────┤
│  环境层：JupyterLab + Python venv + 共享数据目录│
└─────────────────────────────────────────────┘
```

**为什么用 JupyterLab 做环境层**：需求里"实训""课程"这两个词的载体天然是 notebook。每个专项就是一组 `.ipynb`，学生照着 cell 往下跑，输出和图留在页面上，最后能导出成 HTML 实验报告交作业。

---

## 三、三条 Pipeline 的具体实现

### 专项 1：AI 应用开发（表格数据，端到端最完整）

**技术栈**：pandas + scikit-learn + MLflow + FastAPI + Streamlit

| 阶段 | 做什么 | 产出 |
|---|---|---|
| 数据清洗 | 缺失值填充、异常值处理、类型转换、去重 | `data/processed/clean.parquet` |
| 特征工程 | 标准化、One-Hot、衍生特征、用 `sklearn.Pipeline` 固化 | `models/preprocessor.pkl` |
| 模型训练 | 训练 + 交叉验证 + 超参搜索，**每次训练自动记入 MLflow** | MLflow Run（参数/指标/模型） |
| 模型注册 | 把最优模型注册到 MLflow Model Registry，标记 Production | 版本化模型 |
| 部署发布 | 加载模型 → FastAPI 暴露 `/predict` → Streamlit 做交互页 | 可访问的 Web 服务 |

**为什么这套最有说服力**：MLflow 的 UI 能直观展示"跑了 5 组实验，哪组 loss 最低"，这是纯 notebook 展示不出来的。而 FastAPI 的 `/predict` 能被 `curl` 直接调通，是"部署发布"最硬的证据。

**演示亮点**：`curl -X POST http://localhost:8000/predict -d '{"features":[...]}'` 返回预测结果——这一幕比任何 PPT 都有效。

---

### 专项 2：大数据应用开发（Spark 分布式）

**技术栈**：PySpark（local 模式）+ Spark SQL + Parquet

| 阶段 | 做什么 | 产出 |
|---|---|---|
| 大数据清洗 | Spark DataFrame API 处理百万行级数据 | Parquet 分区表 |
| 特征工程 | Spark ML `VectorAssembler` + `StandardScaler` | PipelineModel |
| 分布式训练 | Spark MLlib 训练（逻辑回归/随机森林） | 模型 |
| 部署 | `PipelineModel.save()` → 批处理/流式预测 | 预测结果 |

**验收关键点**：Spark 有内置 Web UI（`http://localhost:4040`），能看到 **DAG 图、Stage 划分、Shuffle 读写量**。这三个可视化一出来，"大数据"这三个字就站住了——普通 pandas 演示是没有这些的。

**前置依赖**：需要 JDK 17（约 300 MB）。`pip install pyspark` 本身不需要编译。

**替代方案**：如果不想装 JDK，可用 DuckDB 替代（`pip install duckdb`，零依赖，直接 SQL 查 Parquet）。但"分布式"的说服力会弱，只适合对大数据要求不严的场合。

---

### 专项 3：大模型应用开发（RAG + Agent）

**技术栈**：Ollama + LangChain + Chroma + Streamlit

| 阶段 | 做什么 | 产出 |
|---|---|---|
| 数据准备 | 文档切块（chunking）、元数据标注 | 文本块 |
| 向量化 | `nomic-embed-text` 生成嵌入，存入 Chroma | 向量库 |
| 检索增强 | 相似度检索 + Prompt 组装 | RAG 链路 |
| 生成 | `qwen2.5` 基于检索结果回答 | 带引用的回答 |
| 部署发布 | Streamlit 做成对话页面 | 可访问的 Web 应用 |

**为什么这条最能打动验收方**：它是"看得见效果"的。上传一份 PDF，问一个问题，系统答出来并给出出处——这个演示不需要懂技术也能判断好坏。

**进阶（可选）**：加一个 Tool Calling 示例（让模型调用计算器/查数据库），展示 Agent 能力。

## 四、课程内容从哪来（不要自己写）

这是最容易踩坑的地方：自己写课程要几个月。直接用成熟开源课程，改个封面就能用：

| 专项 | 推荐课程（开源、可商用） | 规模 |
|---|---|---|
| AI 应用开发 | **Microsoft ML-For-Beginners**（24 课，含 notebook） | 覆盖回归/分类/聚类/部署 |
| | **《动手学深度学习》d2l-zh**（李沐，全 notebook） | 深度学习主线，中文 |
| 大数据应用开发 | **Spark 官方 Examples** + Datawhale 大数据课程 | DataFrame/SQL/MLlib |
| 大模型应用开发 | **Datawhale llm-universe**（中文，RAG/微调/部署全套） | 最贴合国内教学 |
| | **HuggingFace LLM Course**（英文，质量高） | Transformer/微调 |

**做法**：每个专项选 1 门主课程 + 1 门补充，把 notebook 放进 `courses/<专项>/` 目录，配上统一的实验报告模板。工作量从"写课程"降到"整理课程"。

## 六、验收演示脚本（8 分钟）

| 时间 | 动作 | 话术要点 |
|---|---|---|
| 0:00 | 打开 JupyterLab，展示课程目录 | "三个专项，每专项一组实验" |
| 0:30 | 跑 `01-数据清洗.ipynb` | 展示缺失值、异常值处理前后对比 |
| 1:30 | 跑 `02-特征工程.ipynb` | 强调 Pipeline 固化，避免训练/推理不一致 |
| 2:30 | 跑 `03-模型训练` | 切到 MLflow UI：**"五组实验，指标一目了然"** |
| 4:00 | 模型注册 → Production | 展示版本管理 |
| 4:30 | 起 FastAPI + `curl` 调用 | **"模型已经是一个在线服务"** |
| 5:30 | 打开 Streamlit 页面，交互预测 | 可视化发布效果 |
| 6:30 | 切到 Spark UI（4040） | "DAG、Stage、Shuffle——这是分布式" |
| 7:30 | 打开 RAG 页面，上传文档提问 | "大模型专项，带出处的回答" |

**注意**：演示前必须 `Restart Kernel & Run All` 跑一遍，确保每步都有真实输出，不依赖之前的运行状态。

## 七、依赖清单与体积

| 组件 | 安装 | 体积 |
|---|---|---|
| pandas / numpy / scikit-learn / matplotlib | pip | 300 MB |
| mlflow | pip | 150 MB |
| fastapi / uvicorn / streamlit | pip | 100 MB |
| pyspark | pip | 300 MB |
| **JDK 17**（Spark 需要） | 安装包 | 300 MB |
| langchain / chromadb / sentence-transformers | pip | 800 MB |
| Ollama + qwen2.5 + nomic-embed-text | 安装包 + pull | 1.5 GB + 5.2 GB |

**合计约 9 GB**（不含已有 PyTorch）。全部 pip 安装，除 JDK 和 Ollama 外无需管理员权限。

## 八、可选增强（时间够再做）

| 增强 | 价值 | 成本 |
|---|---|---|
| **nbgrader 自动判分** | 直接对应"实训课程"：发布作业 → 学生提交 → 自动出分 → 反馈 | 低（pip 安装 + 配置） |
| MLflow Model Registry + Webhook | 展示模型全生命周期治理 | 低 |
| Docker 化部署 | 展示工业级发布流程 | 中（需 Docker） |
| 模型监控（Evidently） | 展示数据漂移检测 | 中 |

其中 **nbgrader 最值得加**：它把"课程"从一堆 notebook 变成有作业、有提交、有分数、有反馈的教学闭环，验收方一眼就能看出这不是几个散装的 demo。
