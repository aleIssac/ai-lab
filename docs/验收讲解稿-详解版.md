## 需求② 代码补全与注释生成（5 分钟）

> 这一项对应验收要求里的"把学生从低阶语法纠错中解放"。  
> 我分两块讲：补全和注释，它们走的是**两条完全不同的技术路线**。

### 补全：FIM 填空，不是"猜下一个词"

**【动作】** 打开 `test.py`，末尾输入 `def avg(`

**【讲】**

> 先看补全。这里用的不是普通的对话模型，是 FIM 模型——Fill-In-the-Middle，填充中间。
>
> 区别在哪：普通语言模型是"给你前面的内容，猜下一个 token"；  
> FIM 是把光标**前面**的代码当前缀、**后面**的代码当后缀，一起喂进去，让模型生成中间该有的部分。
>
> 技术上就是三个特殊标记：

```
<|fim_prefix|>光标前的代码<|fim_suffix|>光标后的代码<|fim_middle|>
```

> 所以它不光知道"我写了 def avg("，还知道下面已经有一个函数在等着、知道这个文件里  
> 前面定义过什么变量。这就是为什么它补出来的东西通常能直接用，而不是泛泛的一句 `return x`。

**【停顿】** 等灰字出现

> 现在灰字出来了。这个灰色是 VS Code 的 InlineCompletion 能力——**它没有写进文件**。  
> 学生可以按 Tab 采纳，也可以继续打字、它就自动消失。  
> 这个交互对教学很重要：模型给建议，学生做判断，不是模型替他写。

**【讲】**

> 上下文策略也做了区分：文件 150 行以内，整份喂给模型；超过 150 行，只取光标前后各 60 行。  
> 因为在 1.5B 这个量级上，塞太多上下文反而会稀释注意力。
>
> 延迟：首 token 100 毫秒左右，完整补全半秒到一秒半。这个速度是因为模型小——  
> 1.5B 量化的 qwen-coder-fim，1GB 大小，纯 CPU 推理。
>
> 这里有个工程细节值得说：中间我们加了一个 40 行的代理服务。因为 Ollama 0.40 会忽略  
> Modelfile 里定义的对话模板，不带 `raw: true` 的话，FIM 的特殊标记会被当成普通文本转义掉，  
> 模型收到的就不是 FIM 格式了。所以代理的唯一作用就是给请求体补上 `raw: true`，其余原样透传。
>
> 还有一个小坑：Continue 这类工具是按**模型名字**去选 FIM 模板的，名字里必须同时有 qwen 和 coder，  
> 否则它会发另一套标记，补全永远是空的。这也是最后我们自己写扩展、不用现成插件的原因之一。

### 注释：走对话模板，另一条路

**【动作】** 光标放进 `train_epoch`，按 `Ctrl+Alt+C`

**【讲】**

> 注释生成走的是完全不同的路径。补全是"填空"，注释是"改写"——给它一段代码，  
> 让它返回加了注释的完整代码。这是对话任务，必须用 chat 模板，不能用 FIM。
>
> 所以注释请求绕开了那个强制 `raw: true` 的代理，直连容器内的 Ollama。  
> 同一个模型服务，两种调用方式，因为任务性质不同。
>
> 提示词里写死了五条约束：只输出代码不要解释、逻辑和缩进不许改、函数上方写三引号文档字符串、  
> 关键语句加行内注释、已有注释保留。
>
> 但光靠提示词不够——1.5B 的模型有时候会"顺手优化"你的代码，这是最危险的。  
> 所以输出之后还有一道校验：把模型返回的代码和原文逐行比对，**原文代码行的保留率低于 60%  
> 就直接放弃**，弹窗提示，文件保持原样。行数比原文少也放弃。
>
> 这道校验比提示词管用。宁可这次不加注释，也不能让模型把学生的代码改坏。

**【停顿】** 等文档字符串出现

> 五秒左右出来了。函数上方是中文文档字符串，Args、Returns 都写清楚了，关键语句前面加了行内注释。  
> 代码逻辑一个字没改——因为校验过了。

**【讲】**

> 另一种用法是不选中直接按 `Ctrl+Alt+Shift+C`，给整个文件所有函数加注释。  
> 实现上是先扫出所有函数和类的行号范围，然后**从文件末尾往前处理**——  
> 因为加注释会让行号下移，从后往前就不会影响还没处理的函数位置。

## 需求③ 报错诊断（3.5 分钟）

**【动作】** 终端跑 `python err_demo.py`

**【讲】**

> 第三个是报错诊断。这一项的目标不是"能回答报错"，而是**能定位到具体的变量和形状**。
>
> 输入有三个来源，按优先级：编辑器里选中的内容 → 剪贴板（判断里有没有 Traceback）→ 当前文件的错误诊断。  
> 演示最顺手的是复制终端里的 traceback。

**【动作】** 复制 traceback，回编辑器按 `Ctrl+Alt+K`

**【讲】**

> 提示词里有一张判据表，这是关键。因为小模型如果不给判据，它会把所有错误都当成"其他"，  
> 给一堆泛泛的建议。判据是这样的：
>
> - 出现 `shapes cannot be multiplied`、`size mismatch`、`mat1 和 mat2` → **维度不匹配**
> - 出现 `same device`、`cuda`、`cpu` → **设备不一致**
> - 出现 `nan`、`inf`、`overflow`，或者 loss 变成 nan → **梯度爆炸**
>
> 每一类还给了典型的修复方向：维度不匹配调 reshape 或改构造参数的形状；  
> 设备不一致把模型、输入、标签统一 `.to(device)`；梯度爆炸降学习率、做标准化、加梯度裁剪。
>
> 还有一条硬约束：**不许为了消除报错去改标签形状**。这是实测出来的——  
> 不加这句，模型会把 `y` 的形状改掉，报错确实没了，但模型训练出来的东西是错的。

**【停顿】** 等报告出现

> 输出是固定的四段：类型、定位、修复、优化。定位里会写出具体行号、变量名、形状为什么对不上。  
> 修复给的是能直接替换的代码，不是"你应该检查一下维度"这种废话。
>
> 报告写在新的标签页里，不写进正在编辑的文件——学生可以对照着改，而不是被模型改。

**【讲】**

> 这里也用了上一节说的 system / user 分离。原因很直接：如果把规则和资料塞在同一条消息里，  
> 1.5B 模型会把规则最后一行的「依据：」当成唯一要输出的内容，只回你一行文件名，不写正文。  
> 实测三个问题里有一个会这样。改了之后再加一道兜底：结果短于 40 个字就重试一次。
>
> 边界也要说清楚：维度不匹配、设备不一致这两类判断很稳；  
> 梯度爆炸往往要看多层网络的结构，模型偶尔会把输出形状读错，给的建议不一定能用。  
> 所以我们不把它包装成"什么错都能修"。

## 需求④ 端到端流程实训（7 分钟）

**【讲】**

> 第四个是流程实训，要求覆盖三个专项。我们的做法不是做三个互不相干的 demo，  
> 而是让**同一份业务数据走完全程**：AI 应用、大数据、大模型，三个专项都能挂在这条线上。
>
> 业务场景是客户流失预测。为什么选这个：表格数据、二分类、指标清晰（F1、AUC），  
> 学生容易理解，而且天然能延伸到"上线"和"解释"。

### 第一段：数据（60 秒）

**【动作】** 打开 notebook `01-数据清洗.ipynb`

**【讲】**

> 原始数据 1545 行。第一个格子里 `df.info()` 会暴露一个问题：几个本该是数值的列，  
> 类型是 object。原因不是数据错了，是里面混了 `N/A` 这种字符串，pandas 读到就整列当文本。  
> 这是真实的脏数据形态，不是我们编的示例。
>
> 清洗做了四件事：把 `N/A` 转成缺失值、数值列强制转换、按 `customer_id` 去重、缺失值填充。  
> 去掉了 45 行重复记录，最后 1500 行。
>
> 这里有个教学点：**为什么要按 customer_id 去重**。重复样本会让训练集和测试集出现同一条记录，  
> 模型相当于提前看过答案，指标虚高。这个坑不讲，学生自己很难意识到。

### 第二段：训练与实验追踪（90 秒）

**【动作】** 终端跑 `python src/train.py`

**【讲】**

> 训练脚本做三件事：特征工程、多模型对比、把每次实验记录到 MLflow。
>
> 特征工程是标准流程：类别列 one-hot 编码、数值列标准化，用 sklearn 的 Pipeline 串起来，  
> 保证推理时用的预处理和训练时完全一致——这一点后面上线会用到。
>
> 三个候选：逻辑回归 C=0.1、逻辑回归 C=1.0、随机森林 200 棵树。  
> 为什么放两个逻辑回归：让学生看到同一个模型、只改一个正则化参数，指标会怎么变。
>
> MLflow 记录的不只是指标，还有参数和产物：模型文件、混淆矩阵图都在里面。

**【动作】** 切到 MLflow

> 三条 Run 的实测结果：F1 分别是 0.657、0.657、0.712，AUC 都在 0.94 左右。
>
> 注意这个现象：随机森林 F1 明显更高，但 AUC 反而略低。说明什么——  
> F1 衡量的是某个阈值下的精确率和召回率的平衡，AUC 衡量的是排序能力。  
> 随机森林对少数类的召回更高（0.90），所以 F1 好看，但整体区分度不如逻辑回归。  
> 选哪个要看业务：如果目标是"尽量不漏掉可能流失的客户"，选随机森林；  
> 如果要做风险排序、按分数分层运营，逻辑回归更合适。
>
> 这种"指标之间不一致"的讨论，是这门课真正想教的——不是跑通一个模型，是能解释为什么。

### 第三段：上线（45 秒）

**【动作】** 打开 `8000/docs`

**【讲】**

> 第三段是服务化。训练出来的 `model.pkl` 和 `preprocessor.pkl` 被 FastAPI 加载，  
> 暴露成一个 HTTP 接口。
>
> 关键词是**两个文件一起加载**：模型和预处理器必须配套。如果上线时只更新了模型、  
> 预处理还是旧的，预测不会报错，但结果是错的——这是线上事故最常见的原因之一。  
> MLflow 里我们把两个都当产物存了，就是为了避免这个。

**【动作】** Execute

> 填一个高风险客户：三个月账龄、月费 130、总消费 390、打过 9 次客服电话。  
> 返回概率 0.92，高风险。
>
> 这个接口的存在意义是：模型不再是硬盘上的文件，而是一个可以被前端、被教务系统、  
> 被小程序调用的服务。这是"AI 应用"和"跑了个模型"的分界线。

### 第四段：大模型 RAG（75 秒）

**【动作】** 切到 8502

**【讲】**

> 最后是大模型专项。这里做的不是"接一个聊天接口"，是完整的 RAG——检索增强生成。
>
> 为什么要 RAG：大模型不知道我们课程里讲的内容，直接问它会编。RAG 的思路是  
> 先从我们的文档里检索出相关片段，把片段塞进提示词，让模型**基于资料回答**。
>
> 文档处理：三份技术文档按 Markdown 标题切块，标题作为块的元数据，一共 16 个片段。  
> 切块要按语义边界切，不能硬切 500 字——切断了标题和正文的关系，检索出来就是一段没头没尾的话。
>
> 向量化用的是 TF-IDF，字符级 2-3 gram。这里要说清楚为什么不用 bge 这类语义嵌入模型：  
> 一是离线环境没有模型文件，二是八个片段这个规模，TF-IDF 足够，  
> 三是字符 n-gram 对中文和代码术语都友好，不需要分词。  
> 生产环境换成语义嵌入，检索接口不用改，因为封在 `KnowledgeBase` 里。
>
> 检索是余弦相似度取 top-3，然后拼 prompt：system 放规则，user 放资料和问题。

**【动作】** 点示例问题

**【停顿】** 等结果

> 问的是"矩阵维度不匹配怎么排查"。检索命中三条，第一条是《PyTorch常见错误》里的  
> "张量形状不匹配"，相似度 0.195——这个数值不高，是因为 TF-IDF 算的是词形重合度，  
> 不是语义相似度，但不影响排序，第一名是对的。
>
> 生成的答案分条给出排查步骤，末尾标了依据。这里最重要的不是答案质量，是**可验证性**：  
> 每条结论都能追溯到某个文件的某一节。学生可以自己翻回去核对，这就把"模型是否胡说"  
> 变成了一个可以检查的问题。

**【动作】** 关掉开关，再问一次

> 关掉生成开关，看到的是真正发给模型的东西：前面是检索到的原文，后面是问题和三条约束——  
> 只用资料里的信息、资料不足也要先答已有的部分、末尾列依据。
>
> 这段 prompt 就是 RAG 的全部：检索负责事实，生成负责表达。  
> 学生看到这段，比听十遍概念都清楚。

## 需求⑤ 神经网络超参实验（2 分钟）

**【动作】** 打开 `nn-playground`

**【讲】**

> 第五个是超参实验。先说一个重要的事实：**这个页面里的训练是真的，不是动画**。
>
> 底层是 TensorFlow Playground 的实现，网络的前向传播、反向传播、梯度更新全部在浏览器里  
> 用 JavaScript 跑。你看到的每一条损失曲线、每一帧决策边界，都是当前这组参数真实算出来的。
>
> 这也是为什么它能做对照实验：换一组超参，结果是真的不一样，不是预设好的演示。

**【动作】** 点播放

> 现在这个数据集是螺旋形的，两层就能分开。点播放，看两个东西：  
> 中间是损失曲线，右边是决策边界——边界每帧都在变，是在逐步拟合这个螺旋。
>
> 这几个控件分别对应：隐藏层的层数和每层神经元数、激活函数（ReLU / Tanh / Sigmoid / 线性）、  
> 学习率、正则化（L1 / L2）及其强度、问题类型（分类还是回归）、  
> 数据集、训练集测试集比例、噪声水平、批次大小。
>
> 教学上最有价值的三个对照：
>
> - **加层**：一层分不开螺旋，两层可以——直观看到"深度"的作用
> - **换激活函数**：线性激活无论多少层都只能画出直线，这是非线性为什么必要的证据
> - **调正则化**：正则化太强，边界变得过于平滑，欠拟合；太弱，边界贴着每个点，过拟合

**【动作】** 点「+」加一层

> 加一层之后边界形状明显变了，收敛也更快。右上角会根据迭代次数和最终准确率给一个分数，  
> 这是给学生做练习用的——用尽量少的迭代达到尽量高的准确率。

## 需求⑥ Transformer 可视化（2 分钟）

**【动作】** 打开 `transformer-explainer`

**【讲】**

> 第六个是 Transformer 可视化。这个页面解决的是"大模型内部到底在算什么"这个问题。
>
> 技术上，它把 GPT-2 small 转成 ONNX 格式，用 ONNX Runtime Web 在**浏览器里做真实的推理**——  
> 不是预设的示意图，是模型真的跑了一遍，中间层的张量被取出来画成图。
>
> 流程是这样的：输入句子先做 BPE 分词，每个 token 查词表变成 768 维向量，加上位置编码，  
> 然后进 12 层 Transformer 块，每层里有 12 个注意力头，最后输出层映射到 5 万个词的词表。

**【动作】** 指左侧输入句

> 这句 `Data visualization empowers us to` 被切成 6 个 token。  
> 注意 `empowers` 被切成了 `em` 和 `powers`——这就是 BPE 的特点，词表里没有的整词会被拆成子词。  
> 学生看到这一步，就明白为什么模型对"罕见词"和"错别字"的表现会变差。

**【动作】** 点开 Attention

> 这里是多头自注意力。点开能看到一个矩阵：行是当前 token，列是它能看的前面所有 token，  
> 颜色深浅是注意力权重。
>
> 关键在"掩码"这两个字——生成式模型的注意力是因果的，第 3 个词只能看第 1、2 个词，  
> 不能看第 4 个。所以这个矩阵是下三角的。这一点很多人看可视化图时会忽略。
>
> 12 个头关注的模式不一样：有的盯语法结构，有的盯指代关系，有的盯相邻词。  
> 页面上可以切到不同头去看。

**【动作】** 指右侧概率榜

> 最后是输出：768 维向量映射到 50257 维的 logit，softmax 之后得到概率。  
> 现在下一个词概率最高的是 `visualize`，21%，其次是 `see`。
>
> 这里可以讲一个有意思的点：输入到 `to` 为止，模型想接的是 `visualize`——  
> 它把 "Data visualization" 这个名词又当动词用了一次。这不是 bug，是小模型常见的复读倾向。

**【讲】**

> 补一句我们做的事：这个页面原版是缺失文件的，`ort-wasm-simd-threaded.jsep.mjs` 这个  
> ONNX Runtime 的加载器不在构建产物里，所以推理根本跑不起来，只能看静态图文。  
> 我们从源码依赖里把它补回来，现在控制台零报错，注意力热力图是真的。

# 附：技术细节速查（被追问时用）

## 补全链路

```
编辑器 (code-server)
  └ 自研扩展 ailab.autocomplete
      · 取上下文：文件 ≤150 行全份；否则光标前后各 60 行
      · 拼 FIM：<|fim_prefix|>前文<|fim_suffix|>后文<|fim_middle|>
      └ HTTP → localhost:11435（自研代理，仅补 raw:true）
          └ ollama:11434 → qwen-coder-fim
              · 模型名必须含 qwen + coder，否则 Continue 类工具会选错 FIM 模板
```


```

实测：首 token 94～139ms，完整补全 0.5～1.4 秒。

## 注释链路

```

选中代码 → Ctrl+Alt+C  
└ chat 模板（不能用 FIM，因为是改写任务）  
└ 直连 ollama:11434（跳过强制 raw 的代理）  
└ 输出后校验：原文代码行保留率 < 60% 或行数变少 → 放弃  
└ WorkspaceEdit 写回，保持原换行符

```

整文件模式：先扫函数/类的行号范围，从末尾往前处理，避免行号漂移。

## 诊断链路

```

输入：选区 > 剪贴板（含 Traceback）> 编辑器诊断  
└ system 放判据表，user 放 traceback + 代码上下文  
└ 输出四段：类型 / 定位 / 修复 / 优化  
└ 结果短于 40 字 → 重试一次

```

判据：`shapes cannot be multiplied` → 维度；`same device` → 设备；`nan/inf` → 梯度爆炸。

## RAG 链路

```

data/kb/*.md  → 按 Markdown 标题切块（16 个）→ TF-IDF(char_wb, 2-3gram, 维度 5071)  
问题 → 同向量化 → 余弦相似度 top-3  
└ system: 三条规则  
└ user: [资料1..3] + 问题  
└ ollama:11434 → qwen2.5-coder:1.5b

```

实测：top1 命中《PyTorch常见错误·张量形状不匹配》相似度 0.195，生成 5～14 秒。

## 训练与服务

```

data/raw/customer_churn.csv  1545 行  
→ 清洗（N/A 处理 + 类型转换 + customer_id 去重 + 填充）→ 1500 行  
→ Pipeline（one-hot + 标准化）
