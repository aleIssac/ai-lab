# 部署到新电脑

> 面向：把这套 AI 教学实训环境从当前这台机器搬到另一台 Windows 电脑。
> 当前项目已改造成「自包含」：**目标机只需要 Docker Desktop，不需要 Python，不需要外网。**

---

## 0. 一句话说明

整套东西只有四样：

| 组成 | 大小 | 在哪 |
|---|---|---|
| 镜像 `ai-lab:1.0` | 1.6 GB（导出后） | Docker 镜像库 |
| 镜像 `ollama/ollama:latest` | 3.6 GB（导出后） | Docker 镜像库 |
| Ollama 模型库 | 1.0 GB | 项目里的 `ollama-models/` |
| 项目目录（含扩展、演示站点、数据） | 2.3 GB | 项目本身 |

后两样已经在项目里了，**换机器只需要额外搬两个镜像**。实测整个包 **7.4 GB**
（Docker Desktop 存的是压缩层，`docker save` 出来也只有 5.2 GB，比 `docker images` 显示的 15.4 GB 小很多）。

---

## 1. 目标机要求

| 项目 | 要求 | 说明 |
|---|---|---|
| 系统 | Windows 10/11 64 位 | WSL2 必需 |
| Docker | Docker Desktop（WSL2 后端），已启动 | 唯一硬性依赖 |
| 磁盘 | C 盘 ≥ 15 GB 空闲 | 加载后镜像解压占约 11 GB，落在 WSL2 虚拟盘（默认 C 盘） |
| 内存 | 8 GB 起 | 当前这台就是 8 GB / 20 核，能跑 |
| 端口 | 3000 / 5001 / 8000 / 8080 / 8501 / 8502 / 11434 空闲 | |
| 外网 | **不需要** | 模型、前端资源、扩展全部离线 |

> 如果 C 盘紧张：Docker Desktop → Settings → Resources → Advanced 里把
> "Disk image location" 改到 D 盘，再重启 Docker。

### 2.2 拷到目标机

- U 盘 / 移动硬盘：**必须 exFAT 或 NTFS**（有单个文件超过 4 GB，FAT32 拷不进去）
- 局域网：`robocopy E:\ai-lab-deploy \\目标机\D$\ai-lab-deploy /E /MT:8`

#### 想压成一个包再发？

整个包 7.4 GB，其中 5.2 GB 是镜像 tar（已经是压缩层，再压收益很小）。按推荐顺序：

| 做法 | 命令 | 说明 |
|---|---|---|
| 直接拷文件夹 | 资源管理器拖到移动硬盘 | 最快，推荐 |
| 打成 tar（不压缩） | `tar -cf 部署包.tar 部署包` | Windows 10+ 自带 tar，单文件好传 |
| 打成 tar.gz | `tar -czf 部署包.tar.gz 部署包` | 体积约 6.5 GB，压缩要十几分钟 |

> 别用资源管理器的「发送到 → 压缩文件夹」，7 GB 也很慢且容易中途失败。
> 装了 7-Zip 就用「存储」模式（不压缩）打包，最快。

### 2.3 在目标机上安装

1. 装好 Docker Desktop 并启动（等鲸鱼图标变绿）
2. 双击 `install.bat`

它做三件事：`docker load` 两个镜像 → 检查模型库 → 调 `project\start.bat` 起全部服务。

手动等价命令（出问题时可拆开看）：

```bat
docker load -i images\ai-lab-1.0.tar
docker load -i images\ollama-latest.tar
cd project
start.bat
```

装完浏览器打开 <http://localhost:3000>。

## 3. 方案 B：目标机有外网

传输量小很多（只有项目 1.5 GB），但要重新构建镜像。

```bat
:: 1. 把项目拷过去（不需要 images/ 和 ollama-models/）
:: 2. 构建 + 启动
cd project
docker compose build
docker compose up -d

:: 3. 拉基础模型，再造补全模型
docker exec ollama ollama pull qwen2.5-coder:1.5b
docker cp docker/Modelfile.fim ollama:/tmp/Modelfile.fim
docker exec ollama ollama create qwen-coder-fim -f /tmp/Modelfile.fim

:: 4. 起服务（会自动装扩展、起后端、起门户）
start.bat
```

> 构建参数在 `docker-compose.yml` 的 `build.args` 里（`WITH_BIGDATA` / `WITH_LLM_APP`），别丢。
> 构建过程要联网装 apt / pip 包，国内建议先配好镜像源（Dockerfile 里已用阿里云 PyPI 和 daocloud）。

## 4. 为什么现在能"拷走就能用"

这次换机器前，专门把四处硬编码改成可移植的：

| 原来 | 现在 |
|---|---|
| `docker-compose.yml` 写死 `D:/Environment/Server/ollama/models` | `${OLLAMA_MODELS:-./ollama-models}`，默认就用项目里的 |
| 扩展在 Docker 卷 `ai-lab-ext` 里（镜像本身不带扩展，换机器会全丢） | 挂载 `./docker/extensions`，**扩展跟着项目走** |
| 门户依赖宿主机 Python + 项目外的两个站点目录 | 门户跑在容器里，站点已复制进 `apps/` |
| `start.bat` 写死 `D:\Environment\Server\...` | 先试本机路径，找不到自动从 PATH 找 docker |

## 5. 换机器最容易栽的六个点

1. **模型目录**
   默认读项目里的 `./ollama-models`。如果非要放别处，在 `project/.env` 里写
   `OLLAMA_MODELS=D:/某目录`（`docker compose config` 可验证挂载点）。

2. **U 盘格式**
   导出后单文件最大 3.6 GB（ollama 镜像），FAT32 的 4 GB 限制勉强不触发，但仍建议 exFAT / NTFS。

3. **`.bat` 文件必须是 ASCII + CRLF**
   中文注释会让 cmd（GBK）解析错位、把脚本切碎，现象是一堆
   `'docker' 不是内部或外部命令` 加 `'ecs'`、`'gox'` 这种乱码片段。
   这次已经踩过，改完要校验：无非 ASCII 字节、无裸 LF。

4. **端口占用**
   装完打不开先看 3000 是否被别的进程占了（IIS、其他静态服务器）。
   `netstat -ano | findstr :3000`

5. **首次补全慢**
   模型冷启动要 6 秒以上。自研补全扩展在激活时会发预热请求（失败每 5 秒重试，最多 20 次），
   启动后等半分钟再测，别一上来就判断"补全坏了"。

6. **别把 C 盘塞满**
   镜像加载后占约 11 GB，落在 WSL2 虚拟盘（默认 C 盘）。空间不足时 `docker load` 会报
   `no space left on device`，此时改 Docker Desktop 的磁盘位置。

## 6. 常见故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker not found` | Docker Desktop 没启动 / 没在 PATH | 启动 Docker Desktop；或在 start.bat 顶部把 `DOCKER` 改成实际路径 |
| `docker load` 报 no space left | C 盘不足 | 改 Docker Desktop 磁盘位置，重启 Docker 后重试 |
| 门户 3000 打不开 | 容器里门户没起 | `docker exec -d ai-lab bash -c "cd /home/coder/project && /opt/venv/bin/python tools/serve_portal.py 3000 > /tmp/portal.log 2>&1"`，然后看 `/tmp/portal.log` |
| 8501/8502 打不开 | Streamlit 没起或崩了 | `docker exec ai-lab tail -30 /tmp/st.log`（RAG 看 `/tmp/rag.log`） |
| MLflow 空页面 | 没起或端口没映射 | `docker exec ai-lab tail -20 /tmp/mlflow.log` |
| 补全不出灰色文本 | 扩展没装 / 代理没起 / 模型没加载 | 依次查：`docker exec ai-lab ls ~/.local/share/code-server/extensions`、`curl localhost:11435`、`docker exec ollama ollama list` |
| 补全内容乱、答非所问 | 模型名不对，Continue 的 FIM 模板会选错 | 确认模型是 `qwen-coder-fim`（名字必须同时含 qwen 和 coder） |
| code-server 提示受限模式 | Workspace Trust | 启动参数已带 `--disable-workspace-trust`，若仍出现点 Manage → Trust |

各服务的日志都在容器 `/tmp/` 下：`portal.log`、`mlflow.log`、`st.log`、`rag.log`、`api.log`、`proxy.log`。

## 7. 重装 / 回滚

```bat
:: 停掉并删除容器（不动项目、不动模型、不动扩展）
docker compose down

:: 连 Docker 卷一起删（扩展和模型都在项目里，不受影响）
docker compose down -v
```

需要重新卸载镜像：

```bat
docker rmi ai-lab:1.0 ollama/ollama:latest
```
